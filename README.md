# 藏宝阁角色查询

本地 React + TypeScript 助手。默认使用项目专用 Chrome 保存登录状态，也可连接日常 Chrome，并在后台工作页中执行固定流程：

**扫码登录 → 跨服购买 → 开服时间「3年以上服」→ 角色列表**

二维码、进度、错误和当前页角色结果均显示在助手页面。没有首页、推荐商品、全服角色或全服装备快捷入口。跨服购买链接和角色搜索表单留在同一个隐藏工作页，不再打开前台标签页。

## 使用

```bash
vp install
vp dev
```

1. 访问 `http://127.0.0.1:5173`，首页 **浏览器运行方式** 默认选择 **项目专用浏览器（保存登录）**。本机需安装 Google Chrome。
2. 点击 **开始查询角色**。程序直接启动专用 Chrome，不请求接管日常 Chrome 的调试授权。
3. 已登录时直接继续查询；未登录时在助手页面扫描二维码，并在手机确认。程序处理网站的跨服提示、选择首个可用登录角色并等待网站确认。
4. 自动进入跨服购买，选择「3年以上服」，进入角色搜索后再次确认同一条件，再加载当前页角色表格。最终响应的 `QueryArgs.server_type` 必须为 `3` 才展示结果。

专用模式使用 [Playwright 持久上下文](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)，固定配置目录为 `data/browser-profile/`，默认无前台窗口；在主页扫码后，后续角色查询、采集和资产分析共享同一个浏览器连接。暂停任务保留连接，服务正常关闭会保存配置，下次启动复用持久 Cookie 和 localStorage。网站登录过期或要求额外确认时仍需重新扫码；保存配置不代表永久登录。不要让多个服务同时占用这个目录，也不要将其提交或清理为运行日志。

浏览器方式保存在独立的 `data/browser-settings.json`，不影响截图设置或估价规则。查询、扫码、采集、分析或连接请求仍在执行时禁止切换；切换后旧角色列表就绪状态清空，需重新开始查询。保存配置失败保留原模式；关闭旧连接失败会报告错误，不继续使用已失效的旧工作页。

选择 **连接日常 Chrome** 时，先在日常 Chrome 的 `chrome://inspect/#remote-debugging` 启用远程调试。这个模式支持 macOS，默认读取 `~/Library/Application Support/Google/Chrome/DevToolsActivePort`；自定义用户数据目录可设置 `CBG_CHROME_USER_DATA_DIR`。这里只读取调试地址，不复制日常浏览器配置；新调试会话仍可能弹出允许提示。旧 `.chrome-cbg-profile` 不再使用。

排查原始网页时，可设置 `CBG_SHOW_WORK_PAGES=1` 后启动服务，例如 `CBG_SHOW_WORK_PAGES=1 pnpm dev:stable`。程序会在 Chrome 的独立窗口显示列表，详情进入该窗口的标签栏；停止采集后保留这些页面，便于人工查看错误。运行中请避免手动修改工作页筛选条件；检查结束后可手动关闭标签。取消该环境变量或设为 `0` 后重新启动服务，即恢复默认隐藏模式。

日常 Chrome 请正常启动，不要添加 `--remote-debugging-port` 或 `--remote-debugging-pipe`。新版 Chrome 使用默认用户目录时，这些旧参数会阻止调试服务及界面开关生效；需要完全退出后去掉参数重新打开。程序会检查调试地址对应的端口，区分旧地址失效、连接权限错误和授权握手失败；修复后再次点击开始会重新读取地址。

日常模式采用 [Playwright connectOverCDP](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp)。使用 Chrome 默认用户上下文创建隐藏工作页，并在 [Target.createTarget](https://chromedevtools.github.io/devtools-protocol/tot/Target/#method-createTarget) 时设置 `hidden: true`、`background: true` 和 `forTab: false`，保留创建会话以维持工作页生命周期。隐藏工作页不出现在标签栏，也没有可见浏览器窗口。Chrome 授权提示本身仍需要用户允许，说明见 [Chrome 官方文档](https://developer.chrome.com/blog/chrome-devtools-mcp-debug-your-browser-session)。

`GET /api/browser/settings` 只读取当前方式、连接和忙状态，不启动或重连浏览器。`POST /api/browser/settings/save` 接受 `{ "mode": "dedicated" }` 或 `{ "mode": "daily" }`。日志新增 `browser.disconnected`、`browser.transport_closed`（关闭码与原因）和 `browser.launch_error`，用于区分连接中断、专用浏览器启动失败和网站读取超时。

## 状态与错误

- 开始接口立即返回，后台任务独立等待扫码和导航。状态轮询不会重复点击登录或创建新窗口。
- 页面导航销毁旧执行上下文时会等待新页面；点击成功触发导航后不会重复提交角色。
- 登录依据当前页面服务端注入的 `IsLogin` / `LoginInfo.login`，缺少标记时才参考可见退出入口。二维码、角色选择或登录页尚未结束时不宣告登录成功。
- 历史 Cookie、商品列表地址和 URL 中的服务器编号均不能证明已登录。身份信息只取当前已确认登录的页面数据。
- 页面显示失败步骤编号，例如 `CBG_CONNECTING`、`CBG_SERVER_AGE`，开发终端保留该步骤的原始错误。错误不会被下一次轮询覆盖。
- 网站额外要求安全验证时暂停并报告原因；当前未实现验证控件在助手页面内的交互。查询结果仅显示当前页，不涉及购买。

## 商品 AI 输入原文

执行 `vp run analysis:prepare`，从 `data/cbg.sqlite` 的同一读取快照中，为每件详情完整的商品生成一份完整 UTF-8 文本，保存到 `data/analysis-inputs/`。可指定数据库和输出目录：`node scripts/prepare-analysis-inputs.mjs /path/to/cbg.sqlite /path/to/output`。

每份文本包含商品 ID、详情采集时间，以及 `listings.listing_json` 和 `listings.detail_json` 中已保存的全部内容，包括列表摘要、人物属性、修炼、技能、装备、召唤兽、内丹、坐骑、外观、字段、表格和补充文字。资料以一份文本传入所选 AI；文本内部的字段组织用于阅读和追溯。

文件名是原文的 SHA-256，索引文件记录商品 ID、采集时间、格式版本、内容哈希和对应 TXT。同样资料再次准备会复用原文；价格或详情变化会生成新的原文，旧原文保留。详情未完成的商品计入待补采数量。生成过程只读采集数据库；导出的原文是后续分析的输入快照，分析结果应关联其内容哈希。

该命令用于单独导出。页面发起的分析会将同一格式的完整原文与请求快照保存到 SQLite，不必先运行导出命令。

## 商品分析

访问 `http://127.0.0.1:5173/analysis-preview`，选择 **Codex · ChatGPT 订阅** 或 **DeepSeek · API**，点击 **开始分析已有商品**。首次未连接时会打开连接弹窗；连接完成后自动开始。Codex 使用官方 SDK 和本机 ChatGPT 登录状态，DeepSeek 使用 Pi Agent SDK 和本机已配置的 API Key。连接验证的固定 `READY` 回复与商品分析分别记录。

**分析并发数** 默认 **10**，可修改为正整数，填 **1** 即逐个分析；与抓取并发数分开配置。修改后用于下次开始、继续或重试，运行中锁定输入；刷新页面恢复默认输入值。页面显示本批并发上限、当前在途数量和角色名称。新旧队列都有任务时，默认10并发分配为7个新号、3个老号；空队列的名额可借用，借用中的任务不中断，完成后归还。每个角色独立保存结果；暂停或错误会中断在途项并保留已完成报价，继续时不重做成功项。批次保存实际并发数，接口续跑不传新值时沿用批次配置；裸号计价规则保持不变。

`POST /api/analysis/start` 接受 `{ "provider": "codex", "concurrency": 10 }`；`POST /api/analysis/resume` 和 `POST /api/analysis/retry` 可传 `{ "runId": "批次ID", "concurrency": 2 }`。代码入口 `startAnalysis`、`AnalysisRunner.start` 和 `resume` 的末尾参数为并发数。新采齐的角色会自动填入空闲槽位；未启用资产分析时仍只计算裸号。

- 开始时从 SQLite 固定本批次详情完整的商品快照。一件商品的所有已保存列表与详情字段拼成一份完整文本，一次提交给所选 AI；各角色按配置的并发数处理，结果分别核验并入库。待补采商品继续显示在总列表。
- 批次固定提供方、模型、Prompt 全文、计价参数和复算版本。刷新或关闭页面不停止本机服务中的队列；点击 **暂停分析** 中断当前件，已完成结果保留。继续旧批次使用它原来的设置；修改设置后开始新批次。关闭服务异常退出后的锁最长 120 秒失效。
- **分析模型** 初始选择“默认模型”：Codex 跟随本机 Codex 配置，DeepSeek 沿用连接设置中的模型。也可从下拉框选择具体模型，开始分析、先分析 1 件和全部重新分析都会传入该选择。Codex 的列表由官方 `model/list` 提供，模型能否使用以实际请求结果为准。运行中的批次锁定模型选择；暂停后切换模型会创建新批次，继续原批次仍使用原模型。
- 新批次只比较 **参考估值与挂牌价**，展示金额差额与比例，不计算手续费、总预算、折扣或最高买入价。服务端算金额，AI 核对原文并解释结果；原文引用不符时自动重试一次，登录或额度错误暂停批次。旧购买结论可以在历史批次查看。
- 每件商品先由程序检查当前装备资料，再通过日常 Chrome 已登录的藏宝阁按全服筛选同配置的人物装备和灵饰，读取并核验独立商品页。装备查询独立于 Codex 账号和模型，AI只接收核实后的报价与计算结果；无装备、资料不齐或均不可交易时不创建查询工作页。保存实际筛选条件、原始查询记录、候选网址、读取时间、网页价格和属性、未采用原因。只核对官方藏宝阁具体单件商品，整号价格、搜索摘要、旧攻略、已下架商品和未核实金额不进入估值。
- 装备、灵饰、上古玉魄、宝宝及宝宝装备均使用已登录 Chrome 中的官网搜索表单，按角色已保存的逐件属性填写控件并点击搜索按钮。实际市场请求必须为全服「3年以上服」，没有指定区服或跨服购买区服限制；各类表单实际提交的条件必须与计划一致，网站恢复了额外条件时不采用报价。
- 装备先查同配置，再依次放宽同段宝石、相邻一段宝石及普通配置；保留核心特技、特效和属性核验。单轮最多读取3页、60条列表候选和20个详情，预算为180秒；宝宝单轮预算为240秒，最多3页、60条候选和20个详情。各查价阶段有进展时在15分钟续查预算内最多自动续查4轮；无进展、读取失败或达到上限时保存进度并暂停。有限样本和未读完范围均明确记录。
- 每件装备、宝宝和宝宝装备保存搜索入口、实际条件或控件操作、筛选阶段、页码、全服请求证据、候选链接、读取时间、价格和匹配差异。在分析详情的逐件查价卡片中可查看关联搜索记录。暂停恢复会保留本任务已完成项目和历史查询记录，只重查未完成部分；选择 Codex 或 DeepSeek 只影响后续 AI 解释。
- 人物装备、灵饰、宝宝及宝宝装备按官网固定结果顺序收集前10件不同的有效在售商品，计算人民币挂牌价的算术平均值；普通环装或白板也实际搜索，不以默认价格跳过。未读完时保存断点继续查询；结果已读完但不足10件时注明实际数量与样本限制。相近资产使用平均价，同时保留范围与配置差异；少样本或价差超过1.5倍会提示限制，不再直接挡掉均价。宝宝装备仅作包价核对，不重复相加；整号市场参考保留中位数口径。关键属性、特技特效、宝石、熔炼、限制及修理失败须核验。正常可修装备耐久不同时展示差异，不编造折扣。绑定、专用、耐久为零或无法修复的装备单独列明，不能直接套价。
- 宝宝按类型、携带条件、成长、资质、技能组合、进阶、特性、内丹和携带装备匹配，不能只看技能数量或按单个技能固定加价。宝宝报价包含其装备时不再重复计入宝宝装备价值。
- 完整裸号计价与已核验的装备、宝宝参考价相加，计算 `(参考估值−挂牌价)` 及其相对挂牌价比例；正数表示挂牌较低，负数表示挂牌较高。范围明确标为裸号本体、人物装备/灵饰与召唤兽个体，锦衣及其他道具仍单列未计价范围。缺资料或可靠报价时显示已算小计及具体缺项，不把未知补成0。
- 推荐榜直接纳入挂牌价低于裸号预估价的角色，无需装备或宝宝配置门槛；其他角色沿用差额阶梯和配置筛选。仅展示资料和分析仍有效的前10件，保持按价差比例排序和已查看筛选。全部商品支持搜索、筛选、分页和历史批次切换。
- 新批次重新查价，不复用旧行情；同一任务暂停、刷新和校验重试使用已保存的查价快照。超过24小时的行情不再作为完整估值，需开始新批次重查。装备浏览器工作页在查询结束、失败或取消后关闭，保留日常 Chrome。试分析数量可选1～3件，按配置的并发数处理，适合先验证资料和查价结果。
- 分析详情可查看当时的商品原文、完整请求、字段依据、每次调用的原始回复和用量，并下载 TXT。原文和完整请求分别保存 SHA-256。SQLite 的 `analysis_runs`、`analysis_tasks`、`analysis_attempts` 和 `analysis_lock` 保存批次、商品快照、调用记录及执行锁；清空采集数据会同时删除这些记录，分析执行中拒绝清空。

单件完整商品原文超过 128 KiB 时保留快照并报告错误，不截断或拆开调用。每次调用最长等待 5 分钟。开发服务固定端口 5173；端口被占用时直接报错。

### Prompt 的存放与调整

`prompts/role-valuation.md` 是项目使用的完整 Prompt，在用户提供的规则上补充平台建议的计价方案，运行时从该文件读取；格式化工具跳过这份文件，版本变更保存在 Git。点击分析页 **分析设置** 可编辑全文，并设置各服务器计价参数。新规则不再使用买入系数、预算或额外费用；建议规则为强壮神速按当前等级一次计价、攻法上限取有效项（同级选攻击）、化圣不叠加等级溢价、69级机缘用公式、坐骑边界取下档且多只分别求和、区服比例相加并只调整角色本体。修炼上限20及以下额外溢价为0。均可修改。

当前“三年外”商品使用全服行情，按商品的服务器 ID 自动匹配热度排名和每 3000 万两金价，无需逐区填写。区服名称与官方目录交叉核对，行情缓存 24 小时，页面可查看来源和读取时间；读取失败不填零。手动修改某区参数后使用手动值，也可恢复自动匹配。手动参数保存到 SQLite `analysis_settings`，保存不会调用 AI。旧版尚未设置的规则和确认项改用页面展示的建议方案，新版手动清空的数值和口径仍保留未知。

说明和表达要求可以直接修改。计价表、公式及挂牌比较规则位于 Prompt 的第三至第九节；修改这部分时，需同时更新 `server/analysis/valuation-calculator.ts` 的复算规则、`profile.ts` 的计价部分指纹及复算版本，并验证对应边界。同步前停止确认金额，结果显示 `NEED_INFO`，避免修改 Prompt 后仍沿用旧算法。

Prompt 第十一、十二节补充装备、灵饰和宝宝的同类比价规则及来源，保留裸号原公式。官方[装备机制](https://xyq.163.com/introduce/jn005.html)、[灵饰机制](https://xyq.163.com/introduce/2014/11/6/5015_474275.html)用于解释价格相关字段；[估价方法说明](https://mhxywukong.cn/valuation-guide)用于参考同类检索和分项追溯。机制资料和旧案例不提供当前金额；资产价格只引用本次已核验快照，保留商品来源和读取时间。

每批的 `analysis_runs.profile_json` 冻结当时的 Prompt、参数及其 SHA-256；商品任务保存完整输入与请求，调用记录保存实际重试请求、原始回复及用量。修改当前文件或参数不覆盖历史快照。算法升级后旧批次只能查看，请点 **按新规则开始分析**，避免新旧算法混算。

资料完整且报价核实后展示裸号参考价、装备参考价、宝宝参考价、合计与挂牌价差；资料不足只显示对应小计和补齐建议。修炼原价表未覆盖的等级、未确认公式及未找到的装备或宝宝报价继续列为缺项。

在采集页点击 **补齐已保存商品的估值资料**，重读人物、坐骑、神器等估值资料，以及当前装备、灵饰、宝宝属性、技能、装备、内丹、提示框和子页，并更新挂牌价。原角色技能资料及分析历史保留；旧原文先存入 `role_source_history`。该操作只重读已保存的商品，不扫商品列表、不推进采集断点。装备或宝宝页未加载、提示框缺属性或图标未识别时保留具体问题，下次仍可补采；旧资产快照不能证明当前资料齐全。

浏览器回归使用临时隔离的无头 Chrome 和本地模拟网站/API，覆盖登录跳转、筛选条件提交、无额外弹窗及助手内结果展示，不读取或操作日常浏览器账号。它不替代真实网站验收。

接口由 Vite 开发服务器提供；`vp preview` 仅预览静态页面。

## 运行日志

连接日常 Chrome 时，只挂接本程序创建的隐藏工作页；不等待用户已有标签页初始化，避免某个无响应的标签页拖住整个连接。日志中的 `browser.websocket_connected` 表示调试握手成功；之后的初始化错误不会再误报成未开启远程调试或等待授权超时。

连接 Chrome、登录状态变化、查询步骤、翻页、商品详情开始/完成及错误会自动追加保存到 `data/logs/run-*.jsonl`。每行是一个独立 JSON，包含时间、运行编号、顺序及耗时；服务异常退出时已写入的记录仍保留。结构化日志不记录 Cookie、二维码内容、登录账号或完整商品 JSON。

首页的 **保存过程截图** 默认开启，采集与分析共用此设置，保存到 `data/runtime-settings.json`，服务重启后沿用。运行中修改会对后续尚未开始的截图生效，已经开始的截图可继续完成。关闭后仍保留文本日志、步骤记录和查价参数证据，稳定性核验照常执行。

首页的 **清理运行记录** 先预览可清理的历史记录及占用空间，确认后只删除这些历史日志和截图；当前活跃运行记录、商品数据、分析记录和数据库备份保留。

开启截图时，本程序创建的 Playwright 工作页按业务步骤截图：开页、切换标签或结果页、读取完成、报错。角色采集与商品分析共用 `data/logs/browser-steps/<运行编号>/`，每步保存 PNG 和同名 JSON，`index.jsonl` 按步骤记录时间、页面编号、角色或资产 key、步骤、截图路径及错误；运行日志中的 `browser.step` 可关联这些文件。登录页面也会保留当时画面，仅保存到本机日志目录；不会挂接或截图用户的其他 Chrome 标签。同时最多执行两次截图，同一页面串行，其余页面停在当前业务步骤等待；截图使用 Playwright 原生 15 秒超时，等待超时或取消清理完成后才继续，失败时保留原始调用日志。装备查价原有严格证据保存在同一运行目录的 `pricing/` 下，仍保留原有稳定性核验和 SHA256。下载运行日志导出 JSON，PNG 留在本地目录。运行数据、日志、截图和本地诊断产物已通过 `.gitignore` 排除。

点击页面中的 **下载运行日志**，可将当前服务的日志导出为一个 `cbg-run-log.json` 文件（`GET /api/logs/export`）。服务重启且尚未开始新流程时，导出上次记录；历史文件保留在 `data/logs/`。状态轮询不会重复记录相同登录状态。日志从本次功能更新后开始记录，不能还原此前未保存的步骤。

## 详情采集与 SQLite 续采

点击已采集列表中的任意一行，会在右侧打开角色详情抽屉；关闭按钮、Esc 或点击遮罩返回列表，保留原分页和滚动位置。默认展示估价概览（价格、服务器、亮点、等级、人物总修、宠物总修和成就），再通过分类标签查看属性表、逐件装备和全部召唤兽。技能只展示名称和等级；召唤兽逐只展示资质、技能、内丹及装备。未采集数据明确标注，不用零替代；补充文字和表格折叠保存，任务中的详情完成后自动更新。移动端使用全屏详情。

进入角色列表后，可设置 **并发抓取数**，默认上限 **6** 个角色，只接受 **2、4、6…正偶数**。开始或继续时，**已保存的未完成任务优先补采**：补采阶段不分新老，独占完整并发池，全部处理完后才开始发现商品。持续采集采用 **新号优先**：有新号排队就优先派发新号；没有新号待派时，用老号补满空闲名额，不必等待新号在途任务全部结束。已经在途的老号继续完成。分析队列仍使用原有7新3老分配，采集策略不改变分析策略。

每个在途角色独占一个详情工作页，同一角色的标签和重读在该页完成；完成后把页面归还池，后续角色复用。详情池按需创建，最多达到配置并发数；一个列表工作页串行核对和翻页，不会每个角色新开一个 Chrome 窗口。默认隐藏模式暂停结束后关闭本轮详情页，保留列表页和浏览器连接；设置 `CBG_SHOW_WORK_PAGES=1` 时保留工作页供检查。点击 **暂停采集** 后，等待在途任务退出；再次开始会恢复待采队列和 SQLite 中分别保存的新旧进度。并发数修改后用于下次开始或继续采集，刷新页面恢复默认值。

代码入口是 `server/crawler/controller.ts` 的 `startCrawl("manual", undefined, { concurrency: 6 })`；`server/crawler/runner.ts` 的 `crawl` 方法接受相同的 `concurrency` 选项。单角色完整读取封装在 `server/crawler/source.ts` 的 `collectRole` 中。接口 `POST /api/crawl/start` 和 `POST /api/crawl/backfill` 均接受 `{ "concurrency": 6 }`，省略时默认 6，只接受正偶数。正常开始/定时采集启用持续巡检；明确的估值补采仍只处理指定待补项后结束。

首页默认每60秒强制刷新一次，必须核实为上架时间倒序；不会把到期时间倒序当成新上架排序。首次检查建立首页边界，后续跨页核对到上次边界，并覆盖同秒商品。发现的新商品先登记SQLite，再由详情池读取。历史采集继续原断点；首页边界和历史断点分开保存，服务重启后均可恢复。旧失败项保留重试，但不阻塞首页发现。历史扫完后仍继续巡检，直到用户暂停或达到定时任务时长。

页面在补采阶段显示“已保存任务优先补采”，持续发现阶段显示“新号优先”，并展示本轮总并发上限、实际在途总数、新号/老号在途与排队数，以及首页下次巡检时间。并发上限不代表始终有足量任务：例如上限10、新号在途0、老号在途4时，实际只有4个角色在采集。原始资料、已完成报价和估价公式保持不变。

界面显示本页第几个角色、正在读取的标签和装备提示进度。每个角色全部标签完成后才提交详情，列表检查和详情采集分别推进，不必等待当前页所有详情处理完再检查后续列表。`pending` / `detail: null` 表示已登记列表摘要、详情尚未完成，并不表示任务结束；打开的详情会自动刷新，完成后可直接切换各标签查看文字、字段和逐件物品属性。

每个标签的 `items` 保存用于估价的核心属性。优先直接读取图片及父元素的 `data_equip_desc`，已有属性不再悬停；仅缺少属性时尝试提示框。装备保留等级、命中、伤害、防御、宝石、特技特效、专用限制、符石和熔炼等数据，移除背景故事和通用功效。技能保留名称、明确类别及等级，内丹保留名称和层数，界面不展示 `skill_type` 等内部键。

召唤兽通过头像的 `data_idx` 索引逐只切换，独立保存到该标签的 `pets` 数组，包含资质、成长、技能名称、内丹和装备属性。界面逐只展开，并显示已采集数量；页面数量与识别入口不一致时将该商品标为待重试，继续处理后续角色，不把第一只当作整组完成。技能作用不采集进估价 JSON。

对外 JSON 使用核心数据格式：不再逐 tab 重复复制隐藏的 `equip_desc_value`，不为每次悬停保存整页快照，去除重复身份字段、图片地址、推荐跟踪参数及原始页面对象。原始详情以 gzip 压缩后保存在 SQLite 的 `role_sources` 表中，供后续核对。旧采集版本在续采时会更新原商品记录，补抓完整宝宝和逐件属性。

- 按截图中的七个标签采集：人物/修炼、技能、道具/法宝、召唤兽/孩子、坐骑、锦衣/外观、玩家之家；同时读取可识别的子标签、召唤兽/孩子条目及悬停提示。保存可见参数、表格、元素数据和商品原始对象，保留 `AllEquip`、`AllSummon` 等嵌套装备与宝宝数据，不只保存概览。
- 打开详情前先悬停列表项，重新读取 `href`、图片 `data_*` 属性和隐藏的摘要 JSON，再查库。主键为 `服务器编号:eid`，`data_ordersn` 另外保留；角色 ID、推荐参数或悬停时间不作为商品唯一标识。
- `data_selling_time` 与 `data_create_time` 分别保存为上架时间和创建时间，按中国时区解析；不会从 `reco_request_id`、`mouse_over_begin` 或 eid 的数字片段猜测上架时间。
- 有时间倒序入口时优先使用上架时间，其次使用网站提供的出售到期时间排序。只有排序声明、对应绝对时间字段、页内与采样页之间的顺序均通过检查，才用二分法定位上次断点附近。到期时间与上架时间分别处理，不混用。
- 继续采集时先按已保存的商品链接检查最近成功记录的「是否上架」。只有「已上架」可作锚点；其他状态依次尝试更早的已采集商品。排序可信时用二分定位锚点附近；排序不可信或历史锚点全部失效时，从第 1 页重新核对完整列表。历史未补齐时从锚点附近向后采集，补齐后的后续轮次只检查第 1 页至锚点附近的新增商品。商品下架、同时间发布、重新上架都不能仅凭时间过滤；已完整入库的商品只查列表，不再打开详情。动态列表运行中增删可能移动页边界，因此后续轮次会再次核对并去重。
- 详情全部读取、入库与断点更新在同一个事务中完成。缺少标签、页面加载失败或验证拦截时，不推进失败商品的断点；下次重试该商品。重新上架会更新同一行并重采详情。
- 每次页面操作保留间隔和少量随机抖动；列表按顺序核对，角色详情按配置并发抓取。不修改浏览器指纹、不绕过验证码或限流。遇到登录失效、安全验证或网站繁忙时暂停。

数据位于 `data/cbg.sqlite`（已加入 Git 忽略），使用 Node 内置 `node:sqlite`，要求 Node **22.13+**。表 `listings` 保存商品及完整 JSON，`role_tabs` 保存标签快照，`role_parameters` 保存可见字段和原始对象的字段路径，`crawl_state` 保存最后成功断点，`crawl_lock` 防止两个本地开发服务同时采集。页面按每页 20 条展示全部已采集记录及完整字段，包含亮点、服务器、上架时间与采集时间；任务结束、登录失效或刷新后仍可查看。旧记录未保存服务器名称时显示服务器编号，亮点缺失时使用已有核心摘要。成功断点保存在 SQLite；单条召唤兽详情失败不推进该商品的成功断点，后续角色继续入库，下轮仍会重试失败商品。

### 定时循环扫描

在页面的 **定时循环扫描** 区域选择 **每天循环** 或 **每周循环**。每天循环共用一组执行时间；每周循环勾选星期几，并分别设置各天的执行时间。两套设置会分别保存，只有选中的方式参与调度。每个运行日最多设置并启动 5 段。每段完成后等待下一个时间点；上一段仍在运行时跳过重叠时间点，不排队补跑。**最长运行时长（分钟）** 在同一天设置多个时间点时必填，相邻时间点至少间隔该时长；单时间点可留空，扫描到本次自然结束。到达时长后暂停并保留断点，下一个时间点继续。

计划由本地服务执行并保存在同一个 SQLite 数据库中。关闭或刷新网页不会停止计划；本地服务、日常 Chrome 和电脑需要保持运行。启用计划前需完成登录并进入角色列表；登录未就绪时按钮不可用，接口也拒绝启用。启用时当天已过的时间点不补跑；已经启用的服务重启后，只尝试当天最近一个未处理的到期时间点，更早的时间点跳过。到点未登录时页面提示扫码，可在下个时间点或午夜前登录并自动启动；过时则跳过该段。安全验证、访问频繁、翻页异常或网络错误会暂停计划，处理后点击 **恢复计划**。手动开始采集会关闭计划，手动采集不会计入定时运行记录，也不受定时时长限制。点击 **暂停采集** 会停止当前轮并关闭计划；**关闭计划** 只取消后续启动，当前轮继续执行。采集运行中清空数据的请求会被拒绝，计划和数据保持不变。

```bash
vp test
node scripts/crawl-regression.mjs
vp run test:e2e
```

`test:e2e` 使用隔离的 Chrome 和 `tests/fixtures/` 中的固定模拟数据验证已采集角色界面；页面资源来自本地构建产物，所有请求均被测试拦截，不连接真实藏宝阁或本地采集 API。

详情页选择器基于提供的截图、标签名称及公开展示脚本实现。需要在真实已登录页面上确认当前网站版本；标签结构不匹配时会报告缺失并暂停，而非将不完整内容标记成功。

## 代码结构

- `vite.config.ts` 启动本地服务；`server/api.ts` 处理浏览器、采集、记录和日志接口。
- `server/cbg.ts` 管理登录查询任务，`server/workflow.ts` 执行网站页面流程。
- `server/crawler/controller.ts` 管理采集任务的启动、暂停和状态；`source.ts` 对接真实浏览器页面。
- `server/crawler/resume.ts` 选择续采锚点和页码；`runner.ts` 负责补采、逐页处理和完成状态；`store.ts` 管理 SQLite 数据与断点。
- `server/diagnostics.ts` 保存可导出的关键运行日志；`tests/e2e/` 验证角色界面，`tests/fixtures/` 保存模拟数据；`scripts/*-regression.mjs` 用隔离浏览器验证其余流程。
