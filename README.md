# 藏宝阁角色查询

本地 React + TypeScript 助手。连接日常 Chrome，复用已有登录状态，并在隐藏工作页中执行固定流程：

**扫码登录 → 跨服购买 → 开服时间「3年以上服」→ 角色列表**

二维码、进度、错误和当前页角色结果均显示在助手页面。没有首页、推荐商品、全服角色或全服装备快捷入口。跨服购买链接和角色搜索表单留在同一个隐藏工作页，不再打开前台标签页。

## 使用

```bash
vp install
vp dev
```

1. 在日常 Chrome 打开 `chrome://inspect/#remote-debugging`，启用远程调试（需要支持此功能的新版 Chrome）。
2. 访问 `http://127.0.0.1:5173`，点击 **开始查询角色**。首次连接如有 Chrome 授权提示，选择允许。
3. 已登录时直接继续查询；未登录时在助手页面扫描二维码，并在手机确认。程序处理网站的跨服提示、选择首个可用登录角色并等待网站确认。
4. 自动进入跨服购买，选择「3年以上服」，进入角色搜索后再次确认同一条件，再加载当前页角色表格。最终响应的 `QueryArgs.server_type` 必须为 `3` 才展示结果。

当前自动连接支持 macOS 上的日常 Chrome。默认读取 `~/Library/Application Support/Google/Chrome/DevToolsActivePort`；自定义用户数据目录可设置 `CBG_CHROME_USER_DATA_DIR`。这里只读取调试地址，不复制浏览器配置。旧 `.chrome-cbg-profile` 不再使用。

连接采用 [Playwright connectOverCDP](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp)。使用 Chrome 默认用户上下文创建隐藏工作页，并在 [Target.createTarget](https://chromedevtools.github.io/devtools-protocol/tot/Target/#method-createTarget) 时设置 `hidden: true`、`background: true` 和 `forTab: false`，保留创建会话以维持工作页生命周期。隐藏工作页不出现在标签栏，也没有可见浏览器窗口。Chrome 授权提示本身仍需要用户允许，说明见 [Chrome 官方文档](https://developer.chrome.com/blog/chrome-devtools-mcp-debug-your-browser-session)。

## 状态与错误

- 开始接口立即返回，后台任务独立等待扫码和导航。状态轮询不会重复点击登录或创建新窗口。
- 页面导航销毁旧执行上下文时会等待新页面；点击成功触发导航后不会重复提交角色。
- 登录依据当前页面服务端注入的 `IsLogin` / `LoginInfo.login`，缺少标记时才参考可见退出入口。二维码、角色选择或登录页尚未结束时不宣告登录成功。
- 历史 Cookie、商品列表地址和 URL 中的服务器编号均不能证明已登录。身份信息只取当前已确认登录的页面数据。
- 页面显示失败步骤编号，例如 `CBG_CONNECTING`、`CBG_SERVER_AGE`，开发终端保留该步骤的原始错误。错误不会被下一次轮询覆盖。
- 网站额外要求安全验证时暂停并报告原因；当前未实现验证控件在助手页面内的交互。查询结果仅显示当前页，不涉及购买。

浏览器回归使用临时隔离的无头 Chrome 和本地模拟网站/API，覆盖登录跳转、筛选条件提交、无额外弹窗及助手内结果展示，不读取或操作日常浏览器账号。它不替代真实网站验收。

## 运行日志

连接日常 Chrome 时，只挂接本程序创建的隐藏工作页；不等待用户已有标签页初始化，避免某个无响应的标签页拖住整个连接。日志中的 `browser.websocket_connected` 表示调试握手成功；之后的初始化错误不会再误报成未开启远程调试或等待授权超时。

连接 Chrome、登录状态变化、查询步骤、翻页、商品详情开始/完成及错误会自动追加保存到 `data/logs/run-*.jsonl`。每行是一个独立 JSON，包含时间、运行编号、顺序及耗时；服务异常退出时已写入的记录仍保留。页面仍显示标签和召唤兽采集进度，日志只保存关键节点。日志与估价数据分开保存，不记录 Cookie、二维码内容、登录账号或完整商品 JSON。

点击页面中的 **下载运行日志**，可将当前服务的日志导出为一个 `cbg-run-log.json` 文件（`GET /api/logs/export`）。服务重启且尚未开始新流程时，导出上次记录；历史文件保留在 `data/logs/`。状态轮询不会重复记录相同登录状态。日志从本次功能更新后开始记录，不能还原此前未保存的步骤。

## 详情采集与 SQLite 续采

点击已采集列表中的任意一行，会在右侧打开角色详情抽屉；关闭按钮、Esc 或点击遮罩返回列表，保留原分页和滚动位置。默认展示估价概览（价格、服务器、亮点、等级、人物总修、宠物总修和成就），再通过分类标签查看属性表、逐件装备和全部召唤兽。技能只展示名称和等级；召唤兽逐只展示资质、技能、内丹及装备。未采集数据明确标注，不用零替代；补充文字和表格折叠保存，任务中的详情完成后自动更新。移动端使用全屏详情。

进入角色列表后，点击 **开始采集详情**。程序在另一个隐藏工作页中打开商品详情，逐条处理，并自动点击分页链接或使用网站的 `goto(page)` 跳页。点击 **暂停采集** 后，在当前动作结束时暂停；再次开始会读取 SQLite 断点。

界面显示本页第几个角色、正在读取的标签和装备提示进度。每个角色全部标签完成后才提交详情，当前页所有角色处理完才翻页。`pending` / `detail: null` 表示已登记列表摘要、详情尚未完成，并不表示任务结束；打开的详情会自动刷新，完成后可直接切换各标签查看文字、字段和逐件物品属性。

每个标签的 `items` 保存用于估价的核心属性。优先直接读取图片及父元素的 `data_equip_desc`，已有属性不再悬停；仅缺少属性时尝试提示框。装备保留等级、命中、伤害、防御、宝石、特技特效、专用限制、符石和熔炼等数据，移除背景故事和通用功效。技能保留名称、明确类别及等级，内丹保留名称和层数，界面不展示 `skill_type` 等内部键。

召唤兽通过头像的 `data_idx` 索引逐只切换，独立保存到该标签的 `pets` 数组，包含资质、成长、技能名称、内丹和装备属性。界面逐只展开，并显示已采集数量；页面数量与识别入口不一致时将该商品标为待重试，继续处理后续角色，不把第一只当作整组完成。技能作用不采集进估价 JSON。

对外 JSON 使用核心数据格式：不再逐 tab 重复复制隐藏的 `equip_desc_value`，不为每次悬停保存整页快照，去除重复身份字段、图片地址、推荐跟踪参数及原始页面对象。原始详情以 gzip 压缩后保存在 SQLite 的 `role_sources` 表中，供后续核对。旧采集版本在续采时会更新原商品记录，补抓完整宝宝和逐件属性。

- 按截图中的七个标签采集：人物/修炼、技能、道具/法宝、召唤兽/孩子、坐骑、锦衣/外观、玩家之家；同时读取可识别的子标签、召唤兽/孩子条目及悬停提示。保存可见参数、表格、元素数据和商品原始对象，保留 `AllEquip`、`AllSummon` 等嵌套装备与宝宝数据，不只保存概览。
- 打开详情前先悬停列表项，重新读取 `href`、图片 `data_*` 属性和隐藏的摘要 JSON，再查库。主键为 `服务器编号:eid`，`data_ordersn` 另外保留；角色 ID、推荐参数或悬停时间不作为商品唯一标识。
- `data_selling_time` 与 `data_create_time` 分别保存为上架时间和创建时间，按中国时区解析；不会从 `reco_request_id`、`mouse_over_begin` 或 eid 的数字片段猜测上架时间。
- 有时间倒序入口时优先使用上架时间，其次使用网站提供的出售到期时间排序。只有排序声明、对应绝对时间字段、页内与采样页之间的顺序均通过检查，才用二分法定位上次断点附近。到期时间与上架时间分别处理，不混用。
- 继续采集时先按已保存的商品链接检查最近成功记录的「是否上架」。只有「已上架」可作锚点；其他状态依次尝试更早的已采集商品。排序可信时用二分定位锚点附近；排序不可信或历史锚点全部失效时，从第 1 页重新核对完整列表。历史未补齐时从锚点附近向后采集，补齐后的后续轮次只检查第 1 页至锚点附近的新增商品。商品下架、同时间发布、重新上架都不能仅凭时间过滤；已完整入库的商品只查列表，不再打开详情。动态列表运行中增删可能移动页边界，因此后续轮次会再次核对并去重。
- 详情全部读取、入库与断点更新在同一个事务中完成。缺少标签、页面加载失败或验证拦截时，不推进失败商品的断点；下次重试该商品。重新上架会更新同一行并重采详情。
- 每次处理有间隔和少量随机抖动，串行执行；不修改浏览器指纹、不绕过验证码或限流。遇到登录失效、安全验证或网站繁忙时暂停。

数据位于 `data/cbg.sqlite`（已加入 Git 忽略），使用 Node 内置 `node:sqlite`，要求 Node **22.13+**。表 `listings` 保存商品及完整 JSON，`role_tabs` 保存标签快照，`role_parameters` 保存可见字段和原始对象的字段路径，`crawl_state` 保存最后成功断点，`crawl_lock` 防止两个本地开发服务同时采集。页面按每页 20 条展示全部已采集记录及完整字段，包含亮点、服务器、上架时间与采集时间；任务结束、登录失效或刷新后仍可查看。旧记录未保存服务器名称时显示服务器编号，亮点缺失时使用已有核心摘要。成功断点保存在 SQLite；单条召唤兽详情失败不推进该商品的成功断点，后续角色继续入库，下轮仍会重试失败商品。

### 定时循环扫描

在页面的 **定时循环扫描** 区域选择 **每天循环** 或 **每周循环**。每天循环设置一个每天执行时间；每周循环勾选星期几，并分别设置各天的执行时间。两套设置会分别保存，只有选中的方式参与调度。每个运行日最多自动启动一次。**最长运行时长（分钟）** 可留空；留空时扫描到本次自然结束，填写后到时暂停本次扫描并保留断点，下一运行日继续。

计划由本地服务执行并保存在同一个 SQLite 数据库中。关闭或刷新网页不会停止计划；本地服务、日常 Chrome 和电脑需要保持运行。启用计划时若当天的执行时间已过，会等待下一运行日；已经启用的服务重启后，若当天尚未启动且已过执行时间，会尝试当天的一次扫描，不补跑更早日期；当天已启动过则等待下一运行日。未登录时页面提示扫码，角色列表就绪后自动继续；登录失效、安全验证、访问频繁、翻页异常或网络错误会暂停计划，处理后点击 **恢复计划**。手动开始采集会关闭计划，手动采集不会计入定时运行记录，也不受定时时长限制。点击 **暂停采集** 会停止当前轮并关闭计划；**关闭计划** 只取消后续启动，当前轮继续执行。采集运行中清空数据的请求会被拒绝，计划和数据保持不变。

```bash
vp test
node scripts/crawl-regression.mjs
vp run test:e2e
```

`test:e2e` 使用隔离的 Chrome 和 `tests/fixtures/` 中的固定模拟数据验证已采集角色界面；页面资源来自本地构建产物，所有请求均被测试拦截，不连接真实藏宝阁或本地采集 API。

详情页选择器基于提供的截图、标签名称及公开展示脚本实现。需要在真实已登录页面上确认当前网站版本；标签结构不匹配时会报告缺失并暂停，而非将不完整内容标记成功。

## 代码结构

- `vite.config.ts` 启动本地服务；`server/api.ts` 处理浏览器、采集、记录和日志接口。
- `server/cbg.ts` 管理登录查询任务，`server/workflow.ts` 执行网站页面流程。
- `server/crawler/controller.ts` 管理采集任务的启动、暂停和状态；`source.ts` 对接真实浏览器页面。
- `server/crawler/resume.ts` 选择续采锚点和页码；`runner.ts` 负责补采、逐页处理和完成状态；`store.ts` 管理 SQLite 数据与断点。
- `server/diagnostics.ts` 保存可导出的关键运行日志；`tests/e2e/` 验证角色界面，`tests/fixtures/` 保存模拟数据；`scripts/*-regression.mjs` 用隔离浏览器验证其余流程。
