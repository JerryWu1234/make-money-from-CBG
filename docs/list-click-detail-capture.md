# 从列表点击打开角色详情

浏览器通路的正式采集入口使用当前已完成角色查询的列表页，按 `serverId + eid` 定位唯一可见头像，经过目标可点击检查后点击。程序不预建空白详情页，不用保存的详情 URL 直接跳转。

网站自然打开新标签时，只读取该次点击产生的子页；网站在原标签跳转时，继续使用原标签。读取前同时核对详情地址和页面公开商品身份。详情采集使用“页面已打开”模式，沿用完整字段、版本、商品身份和 partial 校验，不再重复导航。

## 执行顺序

1. 保留原有上架时间、四修门槛、重复商品检查及访问预算。
2. 串行执行头像点击、详情读取、关闭本次子页或后退返回列表，再处理下一件。该来源的有效并发为 1，列表刷新、翻页和悬停也进入同一队列。
3. 返回后检查查询参数（含筛选、排序、页码）与原查询一致。正常采集只关闭本次产生的详情子页，保留原列表及其他用户标签。
4. 补采任务也从列表定位。找不到商品时保留待采任务并停止，不使用历史 URL 绕过列表，不将“未找到”判为已下架。
5. 点击无结果、详情身份不符或返回查询不一致时停止；取消后不再开始排队点击。保留已有资料和断点，不重放结果未知的点击。

扩展与 macOS 输入通路沿用既有 `listing-detail` 语义动作及绑定生命周期，本次没有将它改成 CDP 或直接 URL 导航。

## 验证范围

- 隔离 Chrome 模拟页面验证新标签及原标签、唯一目标及身份检查、连续三次串行处理、无结果不重放、取消保留用户标签、返回条件变化后停止。
- 完整详情根用同一份含人物、技能、装备、宝宝和估值的样本，同时验证原打开方式与已打开模式；已打开模式禁止再次调用 `goto`。
- 兼容回归覆盖 source、controller、watch、重试优先级、适配器及点击检查。

以上是隔离测试范围。本次不连接用户真实 Chrome，不进行官网采集，也不把模拟页面通过视为官网业务验收。
