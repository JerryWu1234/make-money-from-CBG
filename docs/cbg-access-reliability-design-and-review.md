### 2.3 必须保留的限定

- 第7页“宽条件也为空即100%确诊L3”不能作为判定规则。条件过期、真无货、加载失败或筛选未生效均可能为空；宽条件非空也不能证明原查询绝对未受限。
- 固定Profile有助于会话连续性，不保证`fp`恒定；Cookie有效不等于页面查询始终健康。
- `CGEventPost`是软件向Quartz事件流投递事件，不能据此保证真实硬件中断或特定频率的合并事件。MAIN脚本、Proxy包装和跨世界消息也不构成不可观察保证。
- 防休眠不等于锁屏后仍可点击，更不保证浏览器满帧。锁屏、焦点、显示器状态仍须独立检查。
- 本设计沿用网页自身的签名、解密、表单和回调，不逆向生成签名、重放验证令牌或自动处理验证码。
- 所有阶段共用限制状态。已有明确访问拒绝时，切换输入驱动、浏览器模式或Profile不能作为继续任务的路径。

## 5. 目标架构与接口

```mermaid
flowchart LR
  J[采集与市场查询调度] --> G[共享访问闸门]
  G --> U[UiDriver 控制适配器]
  U --> W[官网页面]
  W --> O[PageObserver 观察适配器]
  O --> Q[查询证据与健康判别]
  Q --> V[商品身份与完整性校验]
  V --> D[现有SQLite与断点/查价游标]
  D --> A[估值与展示]
  Q --> G
```

### 5.1 复用边界

- 保留`CrawlSource`业务入口、角色与资产数据模型、市场匹配和估值规则。新增适配层负责执行/观察，不另造一套平行的价格和断点体系。
- 当前Playwright实现是一个适配器；扩展读取加macOS输入是另一个。模式能力显式声明，不支持的操作返回`unsupported`并保留进度，不偷偷回退到另一种模式。
- `UiDriver`提供导航到页面可见入口、填写/选择、点击、滚动和动作结果确认；每次动作走同一访问闸门与页面序列。
- `PageObserver`提供列表/详情快照、业务响应摘要、页面身份、版本与状态变化。校验器只消费普通数据，不依赖Playwright `Page`或扩展API。
- 读取侧、等待、截图/证据、页面版本与商品身份核验均迁出CDP后，MOD-01才可能通过。原生鼠标输入本身不代表零CDP。

### 5.2 关联与数据契约

每项记录至少带：`schemaVersion`、`runId`、`queryId`、`actionId`（无动作的观察可空）、`pageId`、`pageGeneration`、`browserSessionEpoch`、`stopEpoch`、`observedAt`、`receivedAt`、`sourceKind`。

- `queryId`在一次新查询/明确重新核验时生成；规范化条件摘要包含类目、服务器/服龄、条件、页码、排序与查询schema版本。
- DOM Hash不是唯一身份依据。响应、回调、当前页面条件和商品身份必须可关联；旧查询回调、其他页结果、同URL不同商品版本均不得并入。
- 网页时间戳是输入，不能单独证明收到资料早于暂停；本地接收、动作派发及完整快照形成时点分别记录。
- 使用现有市场cursor的版本与迁移字段保留page/history/seen/failed等语义。无法验证旧cursor时从已有规则允许的可核验位置重查，保留历史证据，不伪造耗尽状态。

## 6. P0：共享访问、调度与空结果

### 6.1 作用域与持久化（ACC-02、ACC-03）

共享对象是本服务管理的全部CBG官网任务。相同数据库的多个连接/服务实例必须看到同一状态；沿用项目已有SQLite及租约体系，增加访问状态表和版本字段，不新建独立影子业务库。

建议状态字段：`siteKey`、`revision`、`stopEpoch`、`state`、`reasons`（未解除原因集合）、`occurredAt`、`retryNotBefore`、`lastEvidenceId`、`policyVersion`、`updatedAt`。另有持久许可账本与派发记录，见6.4。字段名可随实现调整，行为和原子性必须保持。

- 首版站点状态保守共享；不得仅以`dedicated/daily`为身份键。切模式、切Profile、启动新轮、启用计划均不清除限制。
- 同库多实例通过事务、原子比较和租约/fencing协调许可；每次最终许可必须完成写事务，不能只读ready或沿用缓存。只有进程内Promise队列不满足跨连接要求。不同数据库、不同电脑或用户手动浏览不在本预算保证内，交付说明必须写清实际协调范围。
- 持久化限制状态成功后才对外报告“限制已保存”。保存失败时本进程仍停止派发，服务进入不可启动状态并明确报错；启动时状态损坏/无法读取也禁止官网任务。不能落盘失败后仍按ready启动。
- 风险更新、许可最终确认、人工恢复均比较当前`revision/stopEpoch`。旧实例或旧确认不能覆盖新风险。

### 6.2 状态机与恢复（ACC-03、ACC-04）

| 当前状态              | 事件                                         | 处理与下一状态                                                                               |
| --------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| ready                 | 明确登录失效/验证码/403                      | 持久增加停止代次，进入needs_action，停止官网派发                                             |
| ready/其他            | 429、明确访问频繁                            | 更新停止代次和最早继续时间，进入cooldown；原因与原始证据保留                                 |
| ready                 | 首次空结果与可信目标基线冲突或有其他明确异常 | 立即进入suspect并冻结终态推进；只允许本事件的一份有界核验/诊断计划，不先提交耗尽再等第二次空 |
| ready                 | 单查询证据不足，但无共享风险证据             | 保持站点状态；暂停该查询链，结果unknown，不推进该链进度                                      |
| suspect               | 对照结束、无法诊断或恢复原查询失败           | 进入needs_action，保存证据；宽查询非空不自动清除疑点                                         |
| cooldown              | 时间到期                                     | 仍不发放普通许可，等待人工继续，不自动回ready                                                |
| needs_action/cooldown | 人工继续，时间与页面核验均满足               | 对当前revision原子确认后回ready；任一条件失败保留暂停                                        |
| 任意                  | 新风险与旧人工确认并发                       | 新停止代次优先；旧确认失败，前端展示新原因                                                   |

`Retry-After`支持秒数及合法HTTP日期，作为最早继续时间下限。缺失或非法时使用显式策略的兜底冷却，不声称知道服务器恢复时间。登录、验证码和频率限制可同时出现，恢复须满足全部未解除条件；保留原因集合，不能用后一次较轻事件抹去人工验证要求。

人工恢复先由用户处理登录/验证，再执行有界页面核验。暂停中允许的核验动作有专用恢复许可，仍受频率和单输入限制，不运行普通采集或循环探测。核验通过与状态清除之间必须再次比较revision。

冻结后：撤销未派发许可、取消排队、关闭或中断本项目持有的工作页/操作；不关闭无关用户标签页。已经取得最终派发授权的动作属于在途工作，请求可能已到服务器，不能保证撤回。冻结提交后不再授予新的普通动作。

已取得资料可做有界本地整理；来源/版本仍有效且完整快照已在停止前形成的资料可按现有事务规则保存。不完整资料存partial。暂停后不推进新的在线扫描断点、市场游标或完成标记；迟到响应只能归档待复核，不能把暂停链补成完成。旧worker即使租约失效也不能更新当前进度。

**业务提交契约：**角色保存、市场快照保存和任何进度写入都携带`owner/fence`、`stopEpoch`、`queryId`、`pageGeneration`及来源版本。在与访问状态共用的SQLite `BEGIN IMMEDIATE`事务内，重新核验当前所有权/租约、停止代次、可运行状态、查询接受结论和商品版本，才原子提交资料及允许的进度；不能在事务外先查ready再无条件写checkpoint/cursor。纯分析计算的提交仍遵守自己的数据版本与owner规则，不冒用在线进度契约。

风险事务与业务事务通过同一写锁确定先后：业务先提交，视为停止前已完成；停止先提交，旧业务事务只能拒绝推进。停止后的证据归档和partial保存走明确的“只归档、不推进”分支，保留原停止代次且不得替换较新complete或当前报价状态。原有`CrawlStore.persistDetail`与分析快照保存需要接入该上下文，不能只复用旧事务外壳就算满足新契约。

### 6.3 业务响应分类（ACC-01）

- 保留登录重定向、可见验证码、页面频率提示和连接错误的独立分类。
- 同源主文档与明确业务路径的XHR/fetch/JSONP纳入访问守卫；`recommend.py`有现成代码证据。其他路径根据当前调用链与fixture逐项登记，不匹配任意`.py`或所有script。
- 对403/429立即分类。HTTP200中的明确拒绝、登录或验证字段，按端点已核验schema分类；未知字段、业务schema变化或不可解析内容进入unknown，不凭猜测错误码认定封禁。
- 旁路副本仅作有大小上限的数据解析，不使用`eval`；保持网页原有JSONP加载、执行与回调行为。解析失败不改变官网返回值或吞掉官网错误。
- 图片、统计日志、无关iframe和静态脚本失败不因该守卫触发站点限制；仍可保留脱敏诊断。AI服务429继续走AI限流，不混入CBG访问状态。

### 6.4 动作许可、并发和时间（ACC-05、ACC-06、CFG-01）

统一预算覆盖列表首次查询/刷新/翻页、可能产生业务请求的悬停、详情/锚点打开、表单查询和市场候选详情。纯内存解析和只读DOM取值不计一次网络动作；一个UI动作可能触发多个请求，因此实际请求数独立观察，不能宣称动作间隔就是所有请求间隔。

许可分为预约、派发前核验、最终确认、完成/取消；在每步检查停止代次、页面代次和取消信号。页面动作保持顺序，但不持有站点全局锁等待整件角色读完。许可排队、页面序列和数据库事务不得循环等待。

许可账本至少持久保存`permitId`、站点、`owner/fence`、run/query/page代次、停止代次、策略版本、状态、预约/最终授权时间和结束原因；状态区分`reserved`、`dispatch_authorized`、`completed`、`cancelled`、`unknown`。最终授权事务同时记录窗口消耗、最后派发时间及槽位占用，再允许执行端发送动作。执行端只接收当前owner/fence的计划。

- 仅预约但从未最终授权的许可可取消并释放预约；最终授权即保守计费，即使随后无法确认是否实际发出，也不退回当期窗口额度。完成释放交互槽，但不抹掉仍在窗口内的派发记录。
- 进程重启/实例接管恢复持久窗口和最后派发时间，不重新获得整份额度。失主过期的未授权预约可回收；最终授权后没有完成证据的动作标记unknown，进入needs_action，先核验页面/副作用，不仅凭租约到期重发或继续操作同一页面。
- owner接管递增fence，旧worker、桥接命令和晚到回执不能更新现有许可或当前进度。跨实例恢复与暂停恢复使用相同代次规则。
- 运行期用单调时钟等待、UTC时间持久记录。墙钟回拨或本进程检测到异常跳变时保守暂停，不提前过期历史额度/冷却；重启后按持久记录恢复，不以进程内计时器消失为额度清零依据。具体跳变阈值与处理配置须写入实施PR。

实施PR必须给出并持久保存以下策略，缺值时本项不得判为完成：最小动作间隔、滚动窗口时长/动作上限、官网交互槽上限、失败冷却兜底、对照开关及基线有效期。所有值可校验、有边界、有版本；测试使用注入时钟和明确策略值。PDF不提供可保证安全的生产默认值，配置数字不能作为实站安全结论。

首版保守模式为一个官网交互槽；离线AI/计算与本地数据库读写不受该槽限制。单槽新增须同步`runner`、API、`CrawlPanel`的合法值、步长、提示、持久配置和测试。

新商品优先但不能无限占用：采用可配置的连续新任务配额，达到配额且旧任务可执行时安排一次旧任务；历史发现也需有推进机会。实现PR写明配额和最大等待的可测边界，不能只放宽并发校验。

详情首次实际打开/读取前等待许可的时间不计读取预算；首次实际读取动作固定截止时间，后续重试和排队不重置截止时间。沿用当前180秒预算时，须验证统一节奏下完整采集能否在预算内完成；不满足时明确调整预算或分段恢复设计并单独评审，不能直接放宽完整性或记作下架。

首页默认仍为60秒固定刷新。旧`random=true`配置表示1..N；读取时标记legacy并显示请求设置与实际有效下限，新的min/max随机设置带schema版本。保存时明确迁移，避免把旧N静默解释成均值。更新策略不清除停止状态或已占用许可。

### 6.5 查询健康与Canary（QRY-01至QRY-03）

结果与访问判断分开保存：

| 维度     | 值                                  | 含义                                                                      |
| -------- | ----------------------------------- | ------------------------------------------------------------------------- |
| 查询结果 | data / empty / unknown              | 已关联当前查询的数据、成功返回的空结果、证据不足                          |
| 访问判断 | observed_normal / suspect / blocked | 本次未见限制且证据可用、存在异常、明确拒绝；observed_normal不证明长期安全 |

成功empty至少有当前条件/页码/排序、加载结束、端点成功或同等页面提交证据、明确空提示，并且没有冲突的访问证据。正常窄条件空结果不因为“空了两次”自动暂停。证据不足才是unknown；新的明确限制覆盖较早正常证据。`empty`描述响应内容，不代表结果已经获准推进；接受结论还须检查该次访问判断。

首次empty若与同一目标查询近期非空证据或其他可信异常证据冲突，立即标为`empty + suspect`、暂不接受并冻结终态推进；不等待第二次才保护游标。单凭宽条件曾有货不能认定窄条件首次空异常。没有异常且成功证据齐全的正常empty，按现有无样本规则处理，不一律阻塞。

异常代次持久保存原查询和当前未提交游标。启用诊断时，核验计划主动安排至多一次同条件目标复核，使用新queryId并保持相同条件摘要；不能依赖普通流程自然再次查询，因为普通流程可能已经到终点。第二次仍成功empty且有有效宽条件基线时，才允许一次Canary；复核非空、失败、缺基线或诊断关闭都保留明确结论并进入人工核实，不自动循环。

基线与所选浏览器会话、类目、服务器/服龄和schema一致、未过期，来自真实非空成功结果。计数不包含取消、旧回调、探针和不完整加载；无可靠基线时不生成“必有货”的假设。原查询复核与Canary分别记录用途，均不能绕过suspect的进度冻结。

每个停止事件/查询异常代次最多一次目标复核和一次宽条件对照，计数、计划步骤和结果持久化，进程重启不能重置；副作用结果未知不重放。明确blocked时不再探测。suspect中的专用计划只含准备、上述两次有界查询及必要恢复/核验，各动作仍走统一预算；失败不再递归扩大条件。

优先用独立诊断页面保留原查询。必须复用原页时，先保存可重放的筛选、排序、页码与页面版本，再逐项恢复并核验；恢复不能靠内存“认为成功”。对照有独立queryId并标记`purpose=diagnostic`，与目标样本、报价、seen、cursor和断点完全隔离。

宽查询非空仅补充诊断证据，目标结果仍按自身证据处理；宽查询空、基线失效或恢复失败均不能确诊L3，进入需人工核实。诊断不会自动解除明确限制。

在任何持久进度写入之前拦截unknown/suspect结果：

- 角色checkpoint、首页水位、历史扫描完成标记、页复核清理与扫描终点。
- 市场搜索mode/page/history游标、结果耗尽、精确/相近模式切换、完成状态与新增报价采用。
- 已保存可信价格保留来源、时间和原状态；未知新查询不把旧价归零、不伪装更新为最新报价。

## 7. P1：观察适配器、扩展与数据一致性

### 7.1 页面观察与回调（OBS-01、OBS-02、BRG-01）

MAIN只读取页面已有对象/查询回调及必要响应旁路；ISOLATED读取DOM证据并向扩展发送数据；Service Worker处理受权本地通信。限制目标域和页面范围，不用任意网址注入权限替代具体范围配置。

优先使用已有DOM、页面对象和`ajax_with_recommend`回调。仅包装fetch不能覆盖当前JSONP；MV3通用网络观察也不等于可以读取所有响应体。XHR、JSONP和渲染快照的每种读取方法都须有独立兼容用例。

回调观察需幂等安装，保留`this`、参数、返回值、错误传播及原回调次数；观察端失败不影响网站本身成功/失败回调。退出时仅清理自己仍拥有的包装，不覆盖页面或其他组件之后的新版本。页面导航/代次变化清理旧观察与等待器。Proxy只是可选实现，不能作为上述行为测试的替代。

### 7.2 本地桥接与信任边界（BRG-02）

首选Native Messaging，相比PDF的本地WS是明确的工程调整：增加本地宿主安装/卸载、固定扩展ID允许名单、协议版本与错误提示。若改选WS，须另外设计仅回环监听、认证、允许来源、心跳和连接重建，并记录选择变更。

MAIN到ISOLATED的DOM事件/postMessage可被页面观察或伪造。Service Worker核对实际sender来源、frame、已绑定tab、页面代次、schema、大小与速率；消息内容里的`origin/tabId`不是授权依据。桥接不传Cookie、登录令牌、完整指纹和任意可执行代码。

本地控制只接受本地调度生成的有限动作计划：查询、筛选、翻页、只读详情与滚动等操作，不提供下单、支付、删除、账户变更、系统授权或任意脚本/系统命令。计划绑定预期语义目标（如“当前第2页的下一页”“商品serverId:eid的详情链接”）、页面类型和目标规则版本，而不是接受页面任意指定的元素ID或坐标。

受保护的ISOLATED逻辑根据本地规则独立定位DOM目标，核对控件类型、允许的选择器/表单字段、href目的与商品身份、页面条件、当前节点和命中关系，将节点关联保存在隔离上下文；MAIN上报的名称、矩形和版本只是候选证据，不能直接成为最终授权。即使sender、tab、frame与矩形都合法，指向另一控件也必须拒绝。

本地端再核对计划/目标证明、站点状态、窗口/活动tab与原生内容区域；需要时使用原生屏幕或辅助功能证据复核。元素框不得授权点击浏览器工具栏、其他应用、系统权限窗口或任意桌面坐标。无法独立确定目标语义就暂停。DOM仍由页面控制，ISOLATED代码隔离不等于页面内容可信；不以此承诺能防御任意被完全篡改的网站。限流、拒绝和审计路径与正常路径同样需要测试。

### 7.3 生命周期、幂等与完整性（BRG-03、DAT-01）

协议包含版本、连接代次、消息ID、序号、确认回执与可重试错误；发送缓冲有上限。Service Worker停止、宿主重启、断线和乱序可恢复已确认位置。先持久接收/处理结果，再确认消费；重复传输不等于重复写业务状态。

数据消息可幂等重传；**未确认的点击等副作用命令不能自动重发。** 恢复后先核验页面业务状态，无法确定执行结果就暂停。消息去重与数据库事务幂等分别验证，不能以单进程缓存充当持久去重。

新旧适配器共同经过现有身份、商品版本和完整性校验：7类角色主标签、人物/技能、装备与仓库、宝宝及其子项、估值来源证明和采集版本。未读、未知、空库存证据不足仍存partial；晚到、旧版本和partial不得覆盖较新的complete。完整数据与允许推进的断点/游标保持现有事务边界。

若新格式无法表达现有证据，则先扩展契约与fixture，再实现传输。新旧通路对同一离线fixture比较，不通过重复访问真实站点来制造双份验收数据。

## 8. P2：macOS输入与模式迁移

### 8.1 桌面状态（NAT-01）

启动检查宿主安装、协议版本、macOS辅助功能/输入权限；需要屏幕证据时另查屏幕录制权限。授权缺失返回具体状态，不循环触发授权弹窗。

只有绑定Chrome窗口和目标tab处于可用前台、屏幕解锁、会话有效且用户未抢占时才派发。用户切窗、抢鼠标/键盘、锁屏、显示器/会话不可用或点击立即停止后，取消排队并冻结输入；保留资料及恢复原因。切回窗口或解锁不自动恢复未知副作用。

防休眠仅随活动任务持有，任务停止/进程退出释放；不得更改用户锁屏或系统安全设置。防休眠与焦点/锁屏检查分别验收。

### 8.2 坐标与动作结果（NAT-02）

目标快照带元素标识、矩形、页面/目标版本、采样时间、滚动/缩放、DPR、窗口及屏幕标识。区分CSS像素、macOS逻辑坐标和物理像素，不直接把`outerHeight-innerHeight`当唯一顶栏偏移。

覆盖Retina、不同缩放多屏、负屏幕坐标、侧栏、工具栏、公告条、窗口移动和页面滚动。框必须与当前绑定窗口的原生内容区域相交且完整处于允许操作范围；无效、过期、遮挡、页面代次变化或窗口不匹配则停止。实现PR必须明确快照有效期和重新采样规则。

点击前重新核验目标语义、受保护节点关联和命中关系，遵守7.2的本地动作计划；矩形在内容区内只是必要条件。输入后验证当前queryId/pageGeneration对应的业务状态变化。发送成功或`isTrusted=true`本身都不等于业务动作完成。部分投递、连接中断或结果未知不重放动作。

### 8.3 全路径迁移与模式互斥（NAT-03、MOD-01）

| 当前路径                       | 新模式要求                                                                   |
| ------------------------------ | ---------------------------------------------------------------------------- |
| 首次进入搜索及表单填写         | 通过浏览器/页面可见入口及页面控件进入并核验实际条件                          |
| 断点远距离跳页                 | 使用网页已有跳页输入/分页控件；无控件则明确unsupported，不调用页面`goto`补回 |
| 角色详情及锚点检查             | 从可核验列表/页面原生链接打开；无法定位入口时保留断点并提示人工定位          |
| 市场搜索及候选详情             | 三类市场源均通过页面控件和主商品链接；详情身份继续独立核验                   |
| DOM读取、等待、版本、截图/证据 | 由扩展/原生证据能力提供；不暗用Playwright/CDP                                |

固定使用所选原生Chrome配置，不周期性改指纹。新模式与Playwright模式同一时刻互斥，切换前协作式停止、收尾并核验资料/租约。旧模式发生限制后不自动切到新模式；回退也保留站点停止代次。

若任一必需能力尚未迁移，则该模式仅为实验、不替换默认方案，也不能宣称端到端零CDP。
