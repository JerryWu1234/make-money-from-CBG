# 详情资料统一核验与失败复现

详情未通过完整性校验时保存部分资料和缺失原因，不进入完整商品库或角色分析。已有的本轮最多三次读取和失败隔离机制继续适用。规则不按角色 ID、商品 ID 或某个装备名称分支。

## 统一规则

- `isNonRoleEquipment` 为物品读取、人物装备校验、空库存判断提供相同分类。分类同时记录 `categorySource`；描述中出现“灵气”等文字形成的推测不能单独证明库存为空。
- 分类针对人物装备范围。读取召唤兽自身资料时，仍需读取其装备属性，不能因为它不属于人物装备而跳过。
- 空库存必须核对穿戴和随身区域的存在、可见性及其他已出现的装备区域。每个物品图标须有独立的已读记录，并有明确的非人物装备依据。未知型号、未读说明、身份不符、隐藏区域及记录数量不足仍然阻止通过。图片和它的外层带元数据节点只计算一个图标。
- 名称从同一图标的有效元素属性、官网 `CBG_GAME_CONFIG.equip_info[modelId].name` 或关联提示框提取。占位文字和属性行不是名称；提示框标题不要求位于第一行。无关联 ID 时，多个不同的可见提示框不能拼接为一件物品。记录 `nameSource`；原元素名称的空白保持原样。
- `readDetailIdentity` 统一读取页面的 `EquipInfo` / `equip` 详情对象，包括不挂在 `window` 上的顶层变量。只接受明确的 `server_id` / `eid`；配置表 `equip_info`、URL 和列表预期 ID 不补缺失身份。多个来源冲突或解析期间身份变化阻止通过。穿戴装备原档补充和本体解析使用相同身份规则。
- 补采失败显示具体商品及原因；转入正常发现阶段清除旧的当前商品和详情进度提示。数据库中的失败原因仍保留。

## 可复现用例

`server/crawler/compact.test.ts` 的“同一分类证据用于任意非人物物品”覆盖多种技能书和材料，以及缺说明、缺名称和重复图标缺对应记录的边界。“占位或属性文字不能遮蔽”覆盖有效名称被无效属性遮挡。

`server/crawler/detail.test.ts` 的“所有角色共用名称”使用临时 Chrome 和本地模拟页面，覆盖官网型号名称、非首行标题、未知名称及多个提示框。成功路径经正常 `CrawlSource.detail` 完整性校验后写入内存 SQLite。原有未知物品和名称空白边界同时保留。

`server/crawler/valuation-identity.browser.test.ts` 覆盖普通全局对象、顶层 `const`、替代详情对象、缺失/非法身份、完整或部分来源冲突、无关配置表和解析期间身份变化。

`server/crawler/watch.test.ts` 验证补采失败后仍正常发现，同时清除上一阶段提示。

```sh
vp test server/crawler/compact.test.ts server/crawler/watch.test.ts --run
vp test server/crawler/detail.test.ts server/crawler/valuation-identity.browser.test.ts --run
vp check
vp run build
```

在 Codex/macOS 中，第二条会启动临时隔离 Chrome，须按 `AGENTS.md` 经沙箱外审批执行；正式源码全量回归 `vp test server src tests --run --maxWorkers=2` 同样适用。限定目录避免运行 `data/diagnostics` 中保留的历史测试副本。不得使用真实采集配置作为浏览器测试目录。

这些用例证明公共规则及失败保护的行为。它们不能证明此前所有真实页面缺失字段的底层原因相同，也不等同于真实网站上的失败商品已补采成功。真实页面确实没有足够证据时，仍保留未完成状态。

## 状态轮询与主线程响应

实时进度使用独立的 `/api/analysis/progress`，只读取批次计数、当前任务及采集状态，不执行排名扫描或传回角色原文。正在执行任务的资产数量在领取任务时生成小型摘要。商品记录、历史与排名仍通过 `analysisOverviewAsync` 分页读取，页面以较低频率刷新，记录返回较晚不能覆盖实时进度。

文件数据库的商品记录和推荐扫描在独立工作线程内使用只读 SQLite 连接，剩余的同步查询不占用采集主线程。工作线程不能迁移数据库、恢复租约、登记任务或启动模型及浏览器；服务关闭时终止线程。内存数据库保留原进程内路径供隔离测试使用。

推荐扫描按时间片让出事件循环，不在让出期间持有 SQLite 迭代器；同参数的并发请求合并。每个读者可独立取消，全部读者离开后停止计算；HTTP 记录请求有12秒计算截止时间。返回前在主线程重新读取批次进度，避免发布计算开始时的旧计数。

`record_versions` 由 SQLite 触发器记录实际列表输入、分析任务结果及来源证明的变化，其他连接的写入同样生效。暖轮询先比较小型版本标识，只有变更或需要展示的角色才读取完整详情。缓存只保留当前候选的小型判断，不缓存角色原文；资料、估值或配置变化时重新计算，报价过期及已查看状态仍即时参与筛选。

扫描保持原有完整候选范围和排序，不能直接截取前十件。异步计算可能与采集、删除、查看或新分析结果同时发生，输出推荐前再次核对有效状态、资料指纹和当前应选任务，避免发布旧结果。

`server/analysis/overview-scheduling.test.ts` 验证重复轮询不重算、单件变化失效、候选后部仍可入选、主线程回调能执行、相同请求合并，以及计算期间的失效或新任务不会恢复旧推荐。`overview-worker.test.ts` 验证真实文件库的跨线程读取、进度并行更新、只读约束和取消关停。`server/api.test.ts` 验证 HTTP 接口等待异步结果。

页面中的本地 HTTP 状态请求超时会明确提示服务未及时响应，并保留上次进度。它与商品的 `page.goto` 导航超时、`locator.evaluate` 元素读取超时、`locator.hover` 悬停超时分别处理；单凭“超时”不能判断为网络错误，也不能证明元素不存在。此次调整没有增加超时上限或商品重试次数。

记录页请求 `includeRanking=false`，每页先选20个商品键及20个分析结果键，再读取展示字段；调用历史也先选30条键。未带该参数的请求继续计算完整推荐候选，切到推荐榜时明确显示加载状态，不将尚未计算显示为零条推荐。

`analysis_source_matches` 用 SQLite 触发器在原始列表或详情实际变化时维护逐任务的精确匹配结果，避免每轮查询重复比较大段原文。原文仍完整保留，其他连接写入、事务回滚、删除重建均更新匹配状态；报价过期及展示前的版本核验继续执行。推荐候选排序仅携带键，之后分批读取版本标识，未变化且不展示的候选不逐条查询完整资料。`source-matches.test.ts`、`overview-scheduling.test.ts`、`api.test.ts` 和 `analysis-progress.pw.ts` 分别覆盖匹配一致性、分页跳过推荐、接口参数及切换视图的加载状态。

## 登录导航中断与实时采集队列

详情进入官方 `login.py` / `show_login.py` 等登录路径时，在正文求值之前识别为 `CrawlAccessError`。上下文在导航中销毁时，只等待一次、最多 1500ms 的登录导航证据；没有证据仍保留原错误，不把任意上下文错误当作安全重读。这里不发起导航、不重新读取商品，也不处理登录或验证本身。

登录、安全验证或访问频率限制会明确暂停采集并返回 `accessIssue`；不自动切换浏览器绕过限制。部分原文保留为未完成任务，其它在途的完整资料仅在当前商品版本仍一致时保存，停止派发后不推进历史断点。开始继续任务时清除旧暂停原因，首页暂停后不再显示已失效的下一次巡检时间。

启动补采仍通过 `retryItems` 核对历史版本与缺失证据；持续派发使用 `pendingItems`，通过待采状态的部分索引仅读取 `pending` / `failed` 的列表元数据。只在实际派发时读取和核对对应商品资料，不因无关分析写入重新读取全部完整角色。所有入库完整性与商品身份规则保持有效。

`access-navigation.browser.test.ts` 经正常 `collectRole` 路径复现实际导航与注入的上下文销毁，并覆盖 HTTP 登录重定向及缺少登录证据的错误；页面均为隔离 Chrome 中的模拟站点。`access-navigation.test.ts` 验证一次等待及取消边界；`watch.test.ts` 验证访问暂停、部分资料、其它在途资料和版本变化；`controller.test.ts` 验证首页可用的暂停状态。`queue-dispatch.test.ts` 在加入1000件完整商品后禁止实时队列读取 `detail_json`，并核对索引与任务状态更新。`tests/e2e/crawl-concurrency.pw.ts` 验证暂停原因及巡检显示。

这些测试不等于官网登录已恢复，也不等于真实采集吞吐已经恢复到启动阶段；现场续采需要另行核对登录和运行窗口。

## 浏览器启动与连接丢失

专用 Chrome 的单次启动预算为60秒；启动超时、未找到可执行文件、配置目录占用及其他启动异常分别显示，原始错误、目录、耗时及可见的子进程PID记录在 `browser.launch_error`。该预算容纳已观察到的约39秒正常启动；不自动删除配置或循环启动。启动超时仅证明初始化未完成，不能据此断言未安装Chrome、目录损坏或登录失效。

运行中的调试连接断开与工作页关闭属于整轮暂停。列表及详情使用统一错误分类；主动取消所关闭的独占页保留原取消原因。断连停止派发，不对已关闭页面重读；已读部分资料留作待采，其他版本仍有效的完整结果可保存，失败页不推进断点，也不把同一连接故障批量计为单品失败。WebSocket日志保留错误对象、底层错误码与关闭码，不能把1006当作具体网络原因。

创建详情页只复用已核验的浏览器连接；列表核验后若连接消失，直接暂停，不在任务派发中隐式重连或再次启动Chrome。

`dedicated-browser.test.ts` 复现180秒启动超时被通用提示覆盖；`work-transport.test.ts` 验证错误不再为空；`watch.test.ts` 与 `controller.test.ts` 验证断连后的待采、断点及暂停状态；`detail.test.ts` 在隔离Chrome中途关闭整个浏览器，验证已读标签保留且仅导航一次。临时空白配置和原配置副本启动成功，只能证明该时点启动可用，不能反推历史启动超时的底层原因。

## 分析增量登记与采集截止时间

详情属性、标签切换和分页的显式 DOM 求值统一使用 `evaluateAll`，在页面主上下文核对唯一目标后读取或点击，避免单元素句柄转换再次等待 `DOM.resolveNode`。已有的商品身份校验、原生悬停、可见性和遮挡保护仍保留；不针对商品或角色编号分支。

`analysis_capture_checks` 持久登记本批次已核验的输入版本、复用结果及其来源证明版本。无关的分析完成、任务领取和锁续期不再触发历史原文重放；新增或修改资料、复用结果或证明失效、报价过期仍触发核验。删除后同key重新出现也获得新版本，事务回滚不会留下虚假版本。该登记不放宽完整性及报价校验，不替代原始资料和调用记录。

同一角色的完整采集与全部重读共用180秒总预算，到期取消并关闭该任务独占的详情页。列表失败停止派发后，给在途详情15秒收尾时间；超过时限的详情被取消，部分资料和原因单独保存。仍须等待页面操作与任务实际退出后才释放采集租约，不能仅用 `Promise.race` 提前返回并留下可继续落库的旧任务。有效且版本未变的完整结果在收尾期内仍可保存，失败列表不推进断点。用户暂停或登录暂停保持各自的状态语义。

`runner-streaming.test.ts` 覆盖无关写入、新增、跨连接变更、来源证明删除与重建Store；`overview-scheduling.test.ts` 覆盖暖轮询不读完整候选详情、轻量计数与请求取消；`watch.test.ts` 覆盖有界收尾及无退出后写入；`detail.test.ts` 在真实隔离Chrome中让页面求值永不返回，验证关闭独占页、保留已读标签且列表页不受影响；`analysis-progress.pw.ts` 验证记录请求被阻塞时进度仍更新，旧记录响应不能覆盖新进度。
