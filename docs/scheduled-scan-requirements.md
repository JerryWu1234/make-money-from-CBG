# 定时扫描需求

状态：已按本需求实现，待合并。

## 目标

在“详情采集与续采”区域设置自动扫描。用户可选择每天执行，或选择每周的运行星期；每个运行日只自动启动一次。用户设置执行时间，并可选填本次扫描的最长运行时长。页面关闭后由本地服务继续调度。

## 已确认的行为

1. **每天循环**：每天使用同一个执行时间，每天最多自动启动一次。
2. **每周循环**：选择一个或多个星期，分别设置各选中日的执行时间；每个选中日最多自动启动一次。未选中的星期不自动启动。
3. 两种循环方式的设置分别保留，只有当前选中的方式参与调度。默认每周循环、一周七天均选中，执行时间均为 09:00。
4. 删除“结束时间”和“每轮间隔”。新增可留空的“最长运行时长（分钟）”：留空时运行到本次自然结束；填写正整数时，从实际启动扫描开始计时，到时请求暂停，保留已入库数据和断点，下一运行日继续。时长到达后不在同一天自动重启。
5. 启用计划前须已登录藏宝阁且角色列表就绪；未就绪时按钮不可用，接口也拒绝启用。计划暂停后的“恢复计划”仍可用于重新准备登录。到执行时间时若未登录藏宝阁，页面提示手动登录；登录且角色列表就绪后，尝试该运行日的一次扫描。
6. 首次采集补齐历史商品，后续沿用现有续采：先补采未完成详情，再检查新增商品；完整商品跳过详情。找不到历史锚点或无法确认排序时，完整核对列表并跳过已完整详情。
7. 登录失效、安全验证、访问频繁、翻页异常、网络超时等致命错误暂停计划并提示处理。用户手动恢复后可重试当日扫描。手动开始采集会关闭计划；手动任务不计入定时运行记录，也不受定时时长限制。手动“暂停采集”会停止本次并关闭计划；“关闭计划”只阻止后续自动启动。采集运行中清空数据的请求会被拒绝，且不会改变计划或数据。
8. 已启用的计划、启用时间和当天是否启动过会持久化。启用时若当天执行时间已过，等待下一运行日；已启用的服务重启后，若当天尚未启动且已过执行时间，则尝试一次。错过的更早日期不补跑。
9. 网页标签可关闭；定时执行期间，本地服务、Chrome 和电脑需保持运行。页面展示本机采用的时区。

## 页面交互

- 提供“每天循环 / 每周循环”选择。每天循环显示一个执行时间；每周循环显示周一至周日的勾选和各天执行时间。取消某天或切换模式时保留原设置。
- 提供可留空的最长运行时长、保存设置、启用或关闭计划按钮。页面显示计划状态、上次结果和预计下次时间。时长到期的结果明确显示“达到时长，已保留断点”。
- 验证所有时间为 HH:mm；每周循环至少选择一天；最长运行时长若填写，必须是大于 0 的整数分钟。
- 修改已启用计划的配置后重新计算下次执行时间；当前扫描不因修改执行时间而中断。若修改了最长运行时长，当前扫描在后续检查时采用新上限。

## 调度规则

1. 到达所选运行日的执行时间后，若该运行日尚未自动启动，立即尝试一次。启用计划时若当天执行时间已过，则等待下一运行日；已启用计划的服务恢复时若当天时间已过且当天尚未启动，则立即尝试一次。一天内不自动启动第二次。
2. 扫描一旦启动，持久记录本地运行日期，避免页面刷新、服务重启或计划关闭再启用造成同一天重复自动启动。若上一运行日的扫描跨过下一次执行时间，跳过已被占用的触发，不排队补跑。
3. 最长运行时长从实际开始采集起计算；等待登录或采集锁期间不计时。到时使用现有协作式暂停路径，保留断点；计划保持启用，等待下一选中运行日。
4. 未设置最长时长时允许本次扫描跨日运行直至完成。任意时刻最多一个采集任务。已有手动任务运行时，定时任务等待其结束。
5. 致命错误进入“需要处理”，等待手动恢复；手动恢复可重新尝试当天。手动暂停关闭计划。时间上限导致的暂停是正常结果，不进入“需要处理”。

## 实现与验收

- 本地服务持有调度器；SQLite 保存计划、最近结果和上次自动启动的日期。服务定时唤醒后按本机时间和持久状态判断是否到期。兼容旧的每日统一时段、每周运行日配置，保留各天原开始时间，旧结束时间与轮次间隔不再使用。
- 复用现有单轮采集、登录、采集锁与断点机制。到达时长时调用采集暂停，并等待本轮彻底结束和释放锁后记录结果。
- 用可控时钟覆盖首次到点、当天去重、隔日与隔周执行、服务重启、跨日长任务、时长到期和留空、登录等待、锁等待、致命错误与手动暂停；用隔离浏览器验证两种配置的保存和刷新恢复。
- 不将隔离测试当作真实藏宝阁定时采集的证明；真实运行需在本地服务、Chrome 和电脑持续运行时验证。
