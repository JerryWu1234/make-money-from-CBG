# 定时循环扫描需求

状态：已按本需求实现，待合并。

## 目标

在“详情采集与续采”区域增加定时循环扫描。用户可切换“每天循环”和“每周循环”：每天循环在每天相同的时段运行；每周循环选择星期几，并为选中的各天分别设置时段。两种方式共用轮次间隔，切换时保留各自的时段设置。服务到时启动一轮现有采集流程；一轮完成后等待配置的间隔，再决定是否在当前运行时段内启动下一轮。

## 已确认的行为

1. 用户选择“每天循环”或“每周循环”。每天循环设置一组开始、结束时间，每天重复；每周循环选择运行日（周一至周日，可多选，至少一天），为每个运行日分别设置开始、结束时间，每周重复。轮次间隔由两种方式共用。切换循环方式时，两套时段设置都保留，只有当前选中的方式参与调度。默认每周循环，一周七天都运行，各天及每天循环的时段均为 09:00 至 23:00。
2. 在运行时段中途启用计划，立即尝试第一轮。
3. 到达结束时间后不启动新一轮；正在执行的一轮继续完成。
4. 首次采集补齐历史商品，之后沿用续采：先补采未完成详情，再检查新增商品；已完整保存的商品跳过详情。
5. 到点时未登录藏宝阁，页面提示用户手动登录；登录与角色列表准备完成后自动继续该轮。
6. 网页标签可以关闭；定时运行期间，本地服务、Chrome 和电脑保持运行。
7. 用户点击“暂停采集”时，暂停当前轮并关闭定时计划；再次运行需要手动启用计划。
8. 运行中遇到登录失效、安全验证或网站提示访问频繁，暂停计划并显示需要处理的原因；用户处理后手动恢复。
9. 找不到仍上架的历史锚点，或列表排序无法确认时，本轮从第 1 页扫到末页重建基线；已完整保存的商品仍跳过详情。
10. 翻页异常、网络超时等其他致命错误暂停计划，显示错误并等待手动恢复。
11. 本地服务在运行时段内重启后，恢复已启用的配置并立即尝试一轮；错过的轮次不补跑。
12. 两种循环方式都支持跨午夜窗口。每周循环中，周五 22:00 至周六 02:00 仍属于周五的运行日；周六即使未勾选，该窗口也会在 02:00 前继续运行。每天循环中，跨午夜时段每天都会重新开始。轮次间隔最短为 10 分钟。

## 页面交互

- 在现有手动采集按钮旁增加“定时循环扫描”设置区：选择“每天循环”时显示每天共用的一组开始、结束时间；选择“每周循环”时显示周一至周日各一行，可分别启用、设置开始和结束时间，并显示每周运行天数。下方设置共用的轮次间隔，提供启用/关闭按钮。切换方式或取消某个星期时保留原设置，切回来可继续编辑。
- 展示计划状态、当前轮状态、上轮完成时间与结果、预计下轮时间；等待登录或需要人工处理时显示明确原因和下一步操作。
- 保存设置时验证时间和间隔：两套设置的时间格式正确，当前方式为每周循环时至少选择一天，最短间隔为 10 分钟，开始与结束时间不能相同；结束时间早于开始时间表示次日结束。展示本机采用的时区。
- 修改已启用计划的设置后立即重新计算下一轮；正在执行的一轮完成后再应用新间隔，不中断该轮。
- 手动“开始采集”与定时计划共用同一个采集任务，不允许同时启动两轮。手动暂停按已确认规则同时关闭计划。

## 运行规则

1. 调度器由本地服务持有，页面只保存设置和读取状态。关闭或刷新网页不改变已启用的计划。
2. 下一轮时间按“上一轮完全结束并释放采集锁的时刻 + 配置间隔”计算。若该时间不在当前循环方式的任何运行窗口内，则每天循环等待次日相同时段，每周循环等待下一个选中运行日的开始时间；错过的轮次不排队补跑。每周跨午夜窗口按开始日期判断星期。
3. 每一轮调用现有续采逻辑。单个商品详情不完整且现有流程仍能完成本轮时，保留待重试状态，下轮优先补采。其他致命错误暂停计划，等待人工处理。
4. 在等待用户登录期间保持计划可见；如果当天窗口结束，则当天不再启动采集，下一窗口再按计划判断。登录二维码过期时需在页面提供重新发起登录的操作。
5. 计划设置与最近一次运行结果持久化；服务进程重启后重新计算下一轮，不依赖页面计时器。若重启时仍处于运行时段，立即尝试一轮，不补跑错过的轮次。
6. 计划区分“已关闭”“等待时段”“等待登录”“运行中”“等待下轮”“需人工处理”。手动暂停进入“已关闭”；致命错误进入“需人工处理”，保留配置供用户恢复。时段内恢复计划立即尝试一轮。

## 实现拆分

1. **服务端调度器**：新增单实例调度状态机，在 `vite.config.ts` 启动本地服务时初始化，不依赖页面或首次 API 请求。负责时间窗口计算、排下一轮、暂停与恢复。定时器只负责唤醒检查；每次检查都以当前时间和持久配置重新判断，避免电脑睡眠或时钟变化造成连续补跑。
2. **采集任务接口**：复用 `server/crawler/runner.ts` 的单轮流程；从 `server/crawler/controller.ts` 暴露明确的“本轮已结束并已释放锁”结果，供调度器等待。调度器与手动按钮统一走单任务入口。服务重启遇到尚未过期的旧采集锁时等待锁到期并重试，不把它误报为本轮致命错误。修改 `server/crawler/resume.ts`：锚点全部失效或排序不可信时退回完整列表扫描，并限制无效锚点探测数量，避免长时间停在定位阶段。
3. **登录准备**：到点时检查 Chrome、登录状态和角色列表；未就绪时沿用 `server/cbg.ts` 的查询/登录流程，在页面展示等待状态，准备完成后再启动采集。现有登录等待有超时，需要让计划保持可恢复状态。
4. **持久化与接口**：在 SQLite 同时保存每天和每周的时段设置、当前循环方式、启用状态、下次运行依据和最近一次结果；新增读取、保存、启用、关闭计划的 API。现有 `server/api.ts` 的请求体验证只校验格式，新增保存接口时需要解析并严格验证字段。
5. **页面**：在 `src/ScanSchedulePanel.tsx` 中提供两种循环方式的设置、控制与状态展示。现有手动入口和历史数据列表继续使用。
6. **诊断与验证**：记录计划启用/关闭、计划触发、每轮开始/完成/失败及等待人工处理。用可控时钟验证时段边界、轮次间隔、服务重启、单实例互斥和手动暂停；用隔离浏览器验证页面配置与状态恢复。

## 验收场景

- 每天循环在任意一天的配置时段内启用，立即运行一轮，此后每天按同一时段重复。每周循环仅在选中星期各自配置的时段启动。每轮结束后按配置间隔判断下一轮，任何时刻最多一轮运行。
- 切换每天和每周循环、保存并刷新页面后，两套时段设置都保留；只有当前选择的方式影响下一轮时间。
- 周一设置 09:00 至 11:00、周三设置 13:00 至 15:00 时，周一 10:00 可启动，周三 10:00 等待到 13:00；修改某天时段后下次调度按新设置计算。
- 关闭或刷新网页，计划仍运行；重新打开页面可以看到计划状态、当前进度和预计下轮时间。
- 到结束时间时，当前轮完成入库并保留断点，不再启动新一轮。
- 到点未登录时不采集；登录且角色列表就绪后自动开始。安全验证或访问频繁时暂停计划，不循环触发请求。
- 点击“暂停采集”后本轮停止且计划关闭；重新启用才会继续。
- 后续轮次不会重复打开已完整商品的详情；未完成详情仍可补采。
- 锚点全部失效或排序不可信时执行完整列表扫描，并用商品唯一键去重，避免漏采或重复入库。
- 本地服务在时段内重启后尝试一轮，错过的触发不排队补跑；网络或翻页异常暂停计划并显示原因。
- 服务重启后即使网页未打开也会恢复计划；旧采集锁尚未过期时等待锁到期，随后只启动一轮。
- 勾选周五而不勾选周六时，周五 22:00 至周六 02:00 的跨午夜窗口按周五时段计算；02:00 后不启动新一轮，进行中的一轮仍完成。下一窗口按下一个选中星期计算。
- 每周循环未选择运行日、间隔小于 10 分钟、开始与结束相同等设置无法保存，并给出明确提示。

## 运行前提

当前项目的 API 运行在本地 Vite 服务进程中，采集使用日常 Chrome 的隐藏工作页。网页标签关闭后仍可调度；本地服务退出、Chrome 关闭或电脑睡眠期间无法执行，到恢复运行时按上面的计划恢复规则处理。
