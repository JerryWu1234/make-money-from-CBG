# 自由文字入榜条件

在“分析设置 → 入榜条件”填写条件并保存，再点击“开始分析”。AI按每件商品的完整已采集资料，逐条返回成立true／不成立false／无法判断null；程序再从上到下计算且／或，决定是否入榜。无需手动解析或确认规则。

条件只有一份列表，且／或从上到下依次合并；例如 `A 或 B 且 C` 按 `(A 或 B) 且 C` 计算。价格可选择“挂牌价小于裸号估值”“挂牌价大于裸号估值”或“不限制”，默认“不限制”。不限制的条目不参与且／或运算。已保存的旧价格条件保留原口径，编辑器标为历史条件；重新选择后使用新的三选一模式。

选择小于或大于时填写百分比幅度，允许小数，默认0%。小于10%按`挂牌价 < 裸号估值 × 90%`判断，大于10%按`挂牌价 > 裸号估值 × 110%`判断；等于比较目标时不满足。切换小于／大于保留幅度；选择不限制后隐藏输入并清除幅度。下浮范围为0至100%，上浮可以超过100%。

## 判断方式

保存设置无需等待AI，也不会启动采集或商品分析。分析时直接将条件原文和商品资料交给AI，不再先转成字段目录中的规则；人物修炼等已采集内容不会因缺少预设字段而直接被拒绝。

每条结果包含原文、布尔值、原始数值及其来源、合计算式和比较结果。程序动态列出本件商品真实存在的证据路径，AI直接引用，不自行拼接。程序检查逐字原文并重新计算sum/count/min/max/identity及比较。单一字面比较中，只有引用、算式、方向和阈值均核实后才校正写反的true／false，保留原判断并显示校正说明；不能证明的结果不自动纠正。

示例：

- 人物装备、灵饰、宝宝装备和召唤兽的合计数量大于8。
- 至少3件等级不低于100级的人物装备。
- 至少一只召唤兽当前技能包含须弥真言。
- 人物等级不低于175级，且门派为化生寺。
- 挂牌价不超过裸号估值的90%。
- 灵饰的最低等级不低于100级。
- 总宝石数量大于等于20：人物装备锻炼等级之和，不含灵饰精炼／星辉石。
- 角色修为大于等于27：攻击、法术、防御、抗法四项当前修炼等级之和；12/20取12，不取上限20，也不计猎术及宠修。

“装备和宝宝合计”沿用本项目已确认的四项口径：人物装备＋灵饰＋宝宝装备＋召唤兽。宝宝装备包含穿戴项及背包中有明确类别证据的散件，同一实例不重复计数。法宝、灵宝、神器、上古玉魄、元身和普通道具不作为人物装备；宝宝饰品不作为宝宝装备。计数包含0级和野生召唤兽，明确排除时才筛掉；交易查价排除项不等于库存不存在。

程序先按官方类型、装备对象等原始证据整理库存事实和缺项，供AI理解；这不是条件字段目录。普通人物装备的宝石合计包含穿戴和背包／仓库实物，灵饰独立分组。按用户确认的口径，装备详情已完整读取且没有宝石信息时按0段；只有名称、详情未读完整、宝石标签存在但数值缺失或原文冲突时仍保留未知。类别待核实但完整详情已确认无宝石的物品贡献0，不影响宝石段数合计。若仅已知部分已达到阈值，可明确给出下界判断；不足以确定时保留null，不把下界写成准确总数。

只估算裸号价格时，条件仍可读取已完整采集的装备、灵饰、宝宝装备和召唤兽资料，不会为判断条件自动补采或查价。实例标识重复时去重；相同名称／描述但标识不同的物品分别计数。

## 无法判断

缺少资料、数量完整性未核验、字段冲突、类型不明、除零及空集合的最值不会按0处理。人物装备与灵饰的类别不明时，单类计数不可确定；两类合并总数可在库存整体完整时计算。

“配置很好”“值得买”等缺少客观标准的条件、采集资料之外的成交价及收益预测显示“无法判断”，并说明具体缺项。不能判断的子句不会被删掉后假装满足。

单条未知不等于满足；最终按三态逻辑合并。例如“不满足 且 无法判断”为不满足，“满足 或 无法判断”为满足；最终无法判断的商品不自动入榜。价格仍按分比较。

## 现有结果与历史

同一原文、相同采集资料和价格上下文的有效逐条判断可以复用。只改且／或关系由程序直接重新合并；修改文字后，开始分析会重新逐条调用AI判断，并复用仍有效的估值和查价证据，不为条件判断自动补采或重新查价。

旧AI状态和旧字段规则结果没有本次引用、计算及资料绑定，不能作为当前入榜依据，需要重新分析。历史分析JSON与原始AI返回保留。新结果与条件原文、源资料哈希、判断协议版本及价格上下文绑定，防止改字、换资料后沿用旧true。

## 运行边界

AI只输出结构化结果，不执行代码、网页指令或网络请求。程序只允许引用本件商品和程序提供的价格上下文，校验路径、原文、有限数值、算术和比较的一致性。原始资料数组索引保留，重复raw／HTML不重复发送。

引用与算式校验不能证明模型没有遗漏物品、选错统计范围或误解条件；复杂文本判断也不能由程序完全验证。模型输出仍需通过独立样本核对。缺资料为null，不能用猜测补齐。

旧的`POST /api/analysis/conditions/compile`及规则审计脚本仅用于历史版本对照，当前分析主流程不再调用它们，也不再使用其字段目录缓存。

## 只读实库审计

新的审计脚本使用不可变的本机归档快照、独立的原始表格／装备描述核算，以及逐条AI结果验证器。完整私有商品资料和结果只保存在本机，不提交源码。

重放已有结果：

```sh
vp exec node scripts/direct-condition-audit.mjs \
  --snapshot /private/tmp/direct-conditions-snapshot.json \
  --replay /private/tmp/direct-condition-responses.json \
  --output /private/tmp/direct-condition-report.json
```

实际调用模型须使用本项目独立授权的登录与独占运行租约，不能借用运行中服务的租约或自动复制其凭据。`local-fixture-replay`只验证本地协议和计算流程，不代表真实模型理解已通过验证。
