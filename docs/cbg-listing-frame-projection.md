# 角色列表观察帧大小修复

2026-11-18 的实站只读诊断确认：已加载 MAIN 的商品列表有 15 行，`QueryResult` 序列化为 751728 字符；仅合并白名单全局和市场配置就有 768924 字符，尚未计菜单等其它字段。MAIN 的消息上限是 200000 字符。旧代码直接传整个 `QueryResult`，包含每件商品的长描述，超限后不发送 render，ISOLATED 因此一直显示 loading、不能确认登录及列表就绪。

修复不提高传输上限，也不减少列表行数。每行只传下游实际使用的 own data 字段：

| 字段                                         | 用途                  |
| -------------------------------------------- | --------------------- |
| `game_ordersn`                               | 与当前 DOM 商品行对应 |
| `eid`、`server_id`、`serverid`、`serverId`   | 商品及服务器身份      |
| `server_name`                                | 列表服务器名          |
| `selling_time`、`create_time`、`expire_time` | 上架、创建、到期时间  |

保留支持的所有行、原顺序和原值，不读取未选中的描述、getter 或 toJSON，不修改网站原对象。超出既有 1000 行边界、存在非法行或投影本身超过预算时，整个 QueryResult 缺省，不截成部分数组或伪造空结果。原 QueryArgs 完整保留；新请求/回调及当前商品身份门槛不变。

这是列表观察传输，不裁剪详情资产。人物、装备、仓库、宝宝、内丹、技能、坐骑等完整资料仍按详情读取流程处理，缺失仍为 partial。四修前置筛选继续从当前 DOM 同行读取，不依赖被省略的列表描述。

验证包括 15 行超过 160 万字符的纯样本、Native decoder 的逆序商品身份与时间逐项对照、冻结原对象及详情资产不变回归。真实临时 Chrome 的实装扩展另用 903161 字符的离线 15 行样本，未触发工具栏即传回全部 15 行及原身份/时间。实站加载 MAIN 修复后，收到 15 行、约 3.7 万字符的快照，loading=false、listingCommitted=true；当时仍有官方 JavaScript 退出链接兼容问题，因此未把该观察写成完整登录或采集通过。
