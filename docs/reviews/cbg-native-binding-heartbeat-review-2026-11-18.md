# 原生首次绑定与暂停心跳复核

服务处于旧暂停状态时，心跳每秒向已经停止的 Runtime 发送一次 `stop`。扩展首次连接、只读绑定和快照上报会使用绑定代次；重复停止命令可能使尚未完成的绑定失效。新增 fake-timer 回归在修复前观察到 3 秒内 3 次重复停止，失败日志保留在本地。

修复只跳过“已停止、没有恢复核验”的重复停止。同代次恢复仍由原握手管理；新风险使恢复代次失效时，即使 `stopped=true` 也在下一次心跳停止，取消旧恢复并释放活动。活动输入、存储/owner 错误仍停止。没有清除暂停账本，没有修改最终许可、恢复票据、权限或输入检查。

两位独立复核者均发现初版遗漏“已停止但仍持有旧恢复代次”的撤销边界；已补条件及回归，两位最终复核均无剩余 finding。其中一位独立运行最终单文件 3/3 通过。复核未读取 memory、未修改文件、未启动浏览器或投递输入。

验证：5 文件、54/54 针对性回归通过；包括首次绑定期间不重复停止、活动输入仍停止、同代次恢复保持、新风险在下一次心跳取消旧恢复、清理后不重复停止。含 Unix socket 的默认沙箱运行先因 `listen EPERM` 失败，沙箱外同组通过，不将失败记为通过。`vp check` 0 错误、29 条既有 warning，构建与 `git diff --check` 通过。本次未重跑全量或隔离 Chrome 套件。

实际安装观察：日常 Chrome 已加载扩展，Native Messaging 注册及宿主 socket 连接已核实；修复后收到真实绑定收据及官网快照。扩展安装晚于已打开的文档时，内容脚本未注入并报 `Receiving end does not exist`，整页刷新后解决。最终收到的是角色搜索表单的绑定，约半秒后收到 `user-stop`，保持停止并保留记录；没有把它标记为商品列表已就绪、恢复握手通过或实际采集输入通过。私钥、安装配置、账户信息和实际登录二维码均不提交。
