# 角色查询诊断字段盘点

本表基于当前源码，不代表藏宝阁全部搜索条件。`server/workflow.ts`、`server/role-search.ts` 显式选择三个服龄并清除单服限制；`server/crawler/page.ts` 和 `server/adapters/native-query-health.ts` 从实际页面的公开 `QueryArgs` 读取其它条件。源码没有门派、修炼、技能等角色筛选项的完整合法值或可核验入口，不能从装备/召唤兽的同名字段推断角色支持。

| 字段                    | 实际读取                                                                                        | 合法值及检查                                                                              | 公开 UI 操作                                                         | 恢复方式                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------- |
| `server_type`           | 已提交 `QueryArgs.server_type`                                                                  | `1`、`2`、`3` 的非重复集合；忽略集合顺序                                                  | 原始工作流通过服龄标签选择；诊断保持这一维度，禁止换服龄             | 每次提交和最终恢复均核对集合与保存值；对照基线必须同服龄 |
| `serverid`              | 已提交 `QueryArgs.serverid`，无值表示全服                                                       | 空值或最多 8 位非负整数；诊断不能改变服务器身份                                           | 原始工作流处理单服限制；诊断保持这一维度，禁止换服                   | 每次提交和最终恢复核对原服务器；对照基线必须同服务器     |
| `price_min`             | 唯一可见、可编辑的 `form input[name=price_min]` 或 `input#price_min` 的实际值；同时核对提交条件 | 空或最多 8 位整数部分、最多 2 位小数的非负数；遵守实际控件 `min/max/step`；不高于非空上限 | Playwright 通过受保护的 `fill`；native 通过 `query-field` 和原生输入 | 保存原值；经同一入口填写、搜索并核对实际提交值           |
| `price_max`             | 与下限相同，字段名改为 `price_max`                                                              | 同价格下限；不低于非空下限                                                                | 同上                                                                 | 同上                                                     |
| `level_min`             | 同数值字段，字段名改为 `level_min`                                                              | 空或最多 8 位非负整数；遵守实际控件 `min/max/step`；不高于非空上限                        | 同上                                                                 | 同上                                                     |
| `level_max`             | 同数值字段，字段名改为 `level_max`                                                              | 同等级下限；不低于非空下限                                                                | 同上                                                                 | 同上                                                     |
| `order_by`              | 实际 `QueryArgs.order_by` 与列表排序                                                            | 诊断支持 `selling_time DESC`、`expire_time DESC`；其它排序显式不支持                      | 唯一可见官网排序链接                                                 | 搜索后重新排序并核验                                     |
| `page`                  | 实际分页文字、提交页码与列表页码                                                                | 正安全整数                                                                                | 唯一可见官网分页链接                                                 | 最后跳回原页，并与原身份一起核验                         |
| 其余 `QueryArgs` 条件键 | 两通路保留公开字段用于身份核对；敏感字段不进入身份                                              | 任何未知键（包括空值）均为 `unsupported_condition`                                        | 不操作，也不静默清除或放宽                                           | 原查询保持暂停，由 UI 列出未知字段并要求人工核对         |

数值格式上限是本地输入边界，不能当作官网完整取值范围。实际控件更严格时采用控件约束；隐藏、禁用、只读、多义控件均不能作为诊断入口。对照只删除同服务器、同服龄维度内已有的受支持数值条件；没有真实、近期、同会话宽条件非空基线时记录 `no_valid_baseline`。

诊断开始前保存实际条件、表单值、控件约束、排序、页码与页面版本。正常的已提交空结果仍可继续；与相同查询近期非空基线矛盾的空结果冻结进度。目标复核、Canary 和恢复结果全部以 `accepted=0` 归档，原普通游标只作为事件快照保存，不由诊断更新。未知条件、关闭诊断、无可用基线和恢复失败均保存结构化状态，并在访问保护 UI 显示下一步。Canary 非空也不能自动恢复采集。

覆盖验证：纯测试覆盖各字段合法值、成对范围、控件约束、未知字段、全部数值条件与排序页码恢复、不可重放恢复、结构化结果持久化及 UI；隔离 Chrome 回归覆盖真实公开表单和扩展观察路径。这里的覆盖不等于真实官网已验证；官网缺失控件或页面结构变化时必须停止自动诊断。

本提交验证：8 个纯测试文件 81 项通过，包含真实 governor/runtime/query/execute 与 host 三个授权模块的 7 项跨层协议回归。原生 helper 自测 34 项通过；两份公开控件隔离 Chrome 用例 7 项通过。诊断先释放普通活动，在已获 governor 动作许可的 dispatch 内轮换 host/helper/扩展授权，再申请新活动断言；旧工作流无权释放新活动。首次诊断目标若不可见，明确暂停，不在授权前额外滚动。更晚的人工停止/硬限制保持优先，旧诊断只归档，不覆盖新暂停状态。
